# Water service

The service provides scoped checkups, settings v4, declaration protection and trust, conclusion cards and layered choices, bounded summary rows, split direct deletion and same-volume quarantine, restore/purge reconciliation, explicit duplicate finding, and growth/forecast updates. The host alone implements `quarantine_reveal`; the internal `quarantine_locate` accepts only IDs for configured quarantine roots or their valid batch directories. All old command shapes remain supported; their response objects include the new M35 keys.

Only junk-clean executes deletion, moves, restore and purge. Duplicate content is read only by dup-finder after `dedupe_start`; declarations and `.git` small files are read only by cleanup-manifest. Other file inspection is metadata only. Quarantine moves do not release space. A journal failure after an action stops later batches and preserves the result before disk reconciliation, without retrying moves. A stored scan or dedupe never grants cleanup authority after restart.

On Windows, build with `cargo build --manifest-path packages/water-service/Cargo.toml` and run the integration suite with `cargo test --manifest-path packages/water-service/Cargo.toml --test service_v1 -- --test-threads=1` from the repository root. Tests create a fresh directory under `.local/` for each fixture, including quarantine roots. Run the read-only example with `cargo run --manifest-path packages/water-service/Cargo.toml --example service_smoke -- <data-directory>`; it checks common locations with cleaning disabled, emits counts only, and opens no windows.

Windows IPC v1 service library, independent of Tauri. `Service::new(ServiceConfig)` accepts the application's private data directory, a `Platform`, and a `FolderPicker`; the host forwards commands to `Service::call`. JSON arguments have exact camelCase keys; responses use the frozen snake_case views.

Scanning and cleaning run on owned background threads. The service serializes task starts and location edits, keeps view projections in memory, persists settings/records through flushed temporary files and rename, and bounds retained scan/clean records to 60. Process command lines remain inside the accepted process-scan snapshot. Callers must keep the service alive until a task completes or cancel/stop and poll it to completion before shutting down.

Read-only hosts must set `clean_enabled: false`. With cleaning enabled, selection consists only of known group IDs; the service derives paths, identities, protection boundaries and rules from its latest scan, validates the plan with junk-clean, persists a SHA-256 token digest, consumes confirmation once, and flushes each journal record to disk. Token entropy comes from fresh standard-library `RandomState` instances; no time/PID seeds or extra FFI are used. The smoke example always disables cleaning and emits only aggregate JSON.

No product window, picker, browser or network access is needed for service checks. Existing fixture junction tests may invoke the local `mklink` fallback. macOS support is not implemented or verified on Windows.

Service text is bilingual: each `_zh` response field has a matching `_en` field, `copy_text` has `copy_text_en`, and errors contain `code`, `message_zh`, and `message_en`. The client chooses which language to display. New saved explanations, event summaries, skip titles, and quarantine group names retain both languages; records saved with only Chinese retain that text as their English fallback.

Scan progress keeps whole-drive space measurements separate from bytes found by rules. Rule progress advances on completed roots, rounded down across 0–90 percent, or 0–40 when a whole drive is selected. Targets sharing a root finish together, including fallback markers; root matching ignores ASCII case. Locations and categories wait until their groups become active or a target finishes, and complete only after all their targets finish. Repeated byte callbacks update activity and bytes without completing roots. An empty or interrupted rule scan reaches its phase endpoint when the scanner returns. Drive locations use `space` after their rule targets finish, remain there while their overview runs, and keep their location names. The `finishing` state covers final processing and persistence at 95 percent; terminal states reach 100 percent.
