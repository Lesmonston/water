# Water 项目立项书

立项日期：2026-10-17。状态：已获用户授权立项；首版范围由总控形成并持续收敛。

## 目标与用户

为使用 AI 编程工具、Python/Node 工具链和本地模型的开发者提供可信的存储盘点、可解释回收建议与受控清理，首版同时考虑 Windows、macOS。

用户的问题不是单纯“文件太多”，而是不了解占用来源、不知道项目是否仍依赖它、担心删除后无法继续工作。Water 的价值假设是减少定位与判断耗时，同时保住模型、对话、开发环境和成果。假设尚待真实样本与付款行为验证。

## 授权与治理

- 用户指定 `smaltalk/water` 为唯一项目工作目录，并指定 Codex 为总控。
- 总控负责需求拆分、任务分派、技术决策、源码研究、集成和阶段验收；子任务只编辑独占文件。
- 用户于2026-10-17明确：架构、规划和验收由总控负责，实现工作用总控写工单、用户外贴的方式交给外部执行者。总控先冻结契约与文件归属，执行者在独立分支提交，主线由总控统一集成；流程见 [人工外贴工作流](CONTROLLER-WORKFLOW.md)。
- 可自主完成项目内可逆开发与验证。真实清理、提权、应用签名采购、对外发布、收款或联系第三方需要结合具体用户授权处理，不能从“立项”推导全部授权。
- 未要求远程仓库或公开开源，本项目先保留本地 Git。产品许可证和最终品牌未定，不使用竞品商标包装产品。

## 竞争事实与机会假设

Jharu、Developer Machine Cleaner 已覆盖 AI/开发缓存识别；Mole、DevCleaner、LLM Cleaner 提供相关付费产品或报价，实际成交与营收未核实。工具数量、双平台和分级本身不是独有优势。源码研究以锁定 commit 为依据，见 [分析汇总](../research/OPEN-SOURCE-ANALYSIS.md)。

优先验证的差异：

1. 能将占用项关联到具体项目、工具版本、已知引用和扫描覆盖边界。
2. 能区分逻辑大小、分配空间、预计回收与实际宿主盘变化，避免共享数据重复计数。
3. 能给出可审计的具体计划，并在执行前识别对象变化、链接替换、活跃使用与目标偏移。
4. 能明确恢复条件与重建成本，保护 Agent 记忆/历史、worktree、微调成果和数据库。

这些是研发方向，不是未经验证的竞品缺失声明或已实现卖点。

## 首版交付目标

### M1 只读 Alpha

用户选择项目根或受支持工具目录，得到分类清单、项目归属证据、风险及成本说明、权限/未知项提示和脱敏导出；没有删除接口。先用受控 fixture 验证，不默认读取 HOME 或全盘。

### M2 清理计划与少量受控执行

在 M1 验收后，为经过版本与安全验证的缓存动作提供预览、用户选择、执行前复核、结果与恢复说明。第一批工具优先 Python/Node 包缓存，模型先盘点；HF revision 或 Docker builder 的具体执行视证据完备程度单独开放。

### M3 双平台 Beta

Windows 与真实 macOS 环境分别完成测试、可用性和打包验证，具备稳定的失败跳过、崩溃中断处理和恢复记录。满足发布门槛后才进入收费实验。

## 首版不承诺

不提供全盘自动删除、不依赖 LLM 决定删除、不自动去重改写模型、不批量删容器卷、不清理凭证与未知数据库、不自动压缩/注销 WSL、不自动清系统快照、不自动删除训练 checkpoint。

云端 token 费用优化、内存/显存卸载、注册表修复及系统加速不属于本产品首版目标。

## 成功与停止条件

技术门槛：保护资产的验收用例零误入默认清理；无法证明目标边界时跳过；引用/共享空间不重复计数；当前阶段不把未知当安全。

价值门槛：用授权样本比较人工处理、现有工具和 Water 的判断耗时、误分类、用户接受建议、实际腾空及后续工作受阻情况。初步以 10–20 名目标用户验证，不把下载量、点赞或问卷意愿当付费证据。

商业假设：免费盘点与基础清理，付费高级管理、归档/迁移和受控自动化；定价未定。不因开发投入而跳过付款验证。若差异价值无法证明，收窄场景或停止扩功能。

## 当前限制

本轮为立项和静态源码研究，没有安装/运行竞品，也没有实测安全漏洞或跨平台兼容。当前主机为 Windows，Rust 工具链和 macOS 执行环境需要在下一阶段确认。没有承诺发布日期或销量。
