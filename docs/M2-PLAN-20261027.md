## 0. 一句话

M2 是在 Water 里打开清理：用户勾选、确认、清理，看到实际释放的空间和前后对比。放行条件沿用路线图：**删除路径的重门通过，并且你在 Water 里亲手清掉 Water 自己的开发垃圾，总控核对结果。**

## 2. 打开清理之前要补的

### 2.1 不修不开

1. **界面**：“准备清理”若在切页之后才返回成功，会在新页面弹出永久删除确认框（G7 审查第 6 条，第四波以前就存在）。焦点在“取消”上，不会误删，但开清理前必须改。
2. **界面**：暂停期间第一次进入趋势、记录或位置页，读取失败后页面停在“正在读取…”，按“重新连接”也不会重新读取（G7 中级）。
3. **宿主**：退出时服务没有真正释放，实例锁却先放掉了（G6 中级，Tauri 内部引用环所致）。开清理后，“清理进行中关窗”必须先停清理、等它停下、释放服务，再放锁。
4. **D**：遍历没有深度上限，极深的目录树可能让服务线程栈溢出（G1 遗留）。真实磁盘上开清理前要处理：超过上限的条目整体跳过并报告，不能崩。
5. **真机清理闭环**：在真窗口里完整走一遍“体检 → 勾选 → 确认 → 清理 → 完成 → 记录”。只对工作树里的合成夹具做，七类真实位置全部关掉（见第 4 节 H3）。

### 2.2 一起修（报告准确性与体验）

- **D**：
  - 被应用立刻重建的同名文件算不算失败（要拍板，第 5 节第 2 条）；
  - 条目的上级目录被移走时报 `skipped/gone`；
  - 残余只统计快照里的对象，释放量不再因为新出现的文件而少报；
  - 硬链接文件不计入释放量。
- **服务**：
  - G2 留下的几处 panic 路径：清理线程里出错时“忙”标志卡住、扫描记录先写盘后更新状态；
  - 锁中毒后进程判断不恢复；
  - 旧计划配错令牌时报 `invalid` 而不是 `stale`。
- **宿主**：
  - 信号文件只更新时间、不截断；
  - `run` 里的接线补测试；
  - 去掉 `\\?\` 后校验路径含义没变。
- **界面**：
  - 切页后仍记录 `stale`（只是不显示提示）；
  - 暂停期间点“停止”失败要有反馈；
  - 剩下会超时的无标记等待都改成有界、带标记；
  - 有记录的清理记录页也检查“清理完成”行的图标。

### 2.3 自清理前要先解决的两件事（总控只读核查所得）

1. **Water 自己的构建目录认不出来。**
   - 各检查器用自定义名字的 `.local/w2-target`、`.local/w3-target` 作为构建目录，里面没有 `CACHEDIR.TAG`，现有规则“带缓存标记的目录”认不出。
   - 处理：规则包加一条“Rust 构建目录”，以根下的 `.rustc_info.json` 为标记。这对所有 Rust 用户都适用，不是只给 Water 开的口子。
2. **离线依赖源会被当成“推荐清理”。**
   - 各工作树的私有 Cargo 目录里，`registry` 子目录带 `CACHEDIR.TAG`，会被认成“推荐清理”，而且默认勾选。
   - 问题是两份离线依赖源头也在 `.worktrees` 里：`.worktrees/a/.local/cargo-home/registry`（D、服务等）和 `.worktrees/ac/.local/desktop-cargo-home/registry`（Tauri）。各波检查器离线编译都从这里复制，清掉它们以后就没法离线编译。
   - 现在按组勾选，不能在组内排除单个条目。
   - 处理：总控先把这两份源头**复制**到 `F:\new\smaltalk\water\.offline-cache\`（只复制、不删），第五波起的清单都从那里取；自清理只添加 `.worktrees` 这个文件夹。复制之后，`.worktrees` 里的原件就只是多余的副本，可以清。

## 3. 自清理里程碑

### 3.1 清什么、留什么

| 类别 | 例子 | 处理 |
|---|---|---|
| Rust 构建目录 | 各工作树 `.local/w2-target`、`w3-target`、`target` | 清（新规则，推荐清理） |
| 私有 Cargo 依赖副本 | 各工作树 `.local/*cargo-home*/registry` | 清（现有缓存标记规则；源头已先复制出去） |
| 测试浏览器配置 | 各工作树 `.local/browser-lab/profile-*` | 清（现有规则，需要确认） |
| 私有临时目录与检查器回执 | `.local/w*-tmp`、`.local/checks` | 不在 M2：没有规则，回执已归档进仓库，留给以后 |
| 验收证据 | `docs/acceptance/**`（在 git 里） | 留 |
| 工作树本身、源码、`.git` | 一百多棵工作树 | 留。删不删旧工作树是另一件事，由你决定，不在 M2 |
| 离线依赖源头 | `.offline-cache\` | 留，不在添加的文件夹里 |
| 日常用的 Water | `.local\release\` | 留，不在添加的文件夹里 |

**体量估计约 35～45 GB。** 依据（总控只读统计，只读名字与大小）：
- 一百多棵工作树的 `.local` 里，可清的几类共约 160 个目录：
  - Rust 构建目录 61 个；
  - 私有 Cargo 目录 61 个；
  - 测试浏览器配置 35 个；
  - 另有几个更大的桌面构建目录。
- 已量完的 50 个合计约 14 GB。按各类平均值推算：构建目录每个约 0.3～0.6 GB（宿主的更大），Cargo 副本约 0.07 GB，浏览器配置约 0.13 GB。
- 全量统计还在后台跑，结果出来后改成实数。

已核实：
- 这些构建目录根下都有 `.rustc_info.json`；
- 浏览器配置目录都同时有 `Local State` 和 `Default`，符合现有“测试用浏览器配置”规则。

### 3.2 步骤

1. 总控把两份离线依赖源复制到 `.offline-cache\`，核对字节一致，更新第五波清单。
2. 第五波各票合入，第三次主线整合检查（含夹具清理闭环）通过，总控编新的 release 版。
3. **你**运行新版 Water：在“扫描位置”里用“添加文件夹”选 `F:\new\smaltalk\water\.worktrees`，做一次体检。
4. 总控只读核对这次体检：
   - 哪些组、各多少；
   - 有没有误入：证据、源码、`.git`、离线依赖源头；
   - 然后给你勾选建议。
5. **你**按“清理所选”并确认。清理按钮只由你按。
6. 总控核对：
   - 操作日志、释放量、前后可用空间；
   - 每棵工作树的 `git status` 与清理前一致；
   - 证据完好；
   - 新建一棵树，从 `.offline-cache` 离线跑一遍检查能通过。
7. 写 M2 达成报告与交接。

清理时不要同时编译，以免构建目录正被写入；被占用的文件会被跳过、报告为部分清理，不会出错。

## 5. 需要你拍板

1. **M2 能清哪几级。**
   - 总控推荐按 ADR-018：“推荐清理”与“需要确认”都能清，后者默认不勾，要你自己勾。现在的界面和服务就是这样做的。
   - 另一个选择是 M2 先只开“推荐清理”，“需要确认”等自清理之后再开。注意“需要确认”里有“下载文件夹里的安装包”“Claude Code 会话临时目录”“node_modules”等你可能还要的东西。
2. **被应用立刻重建的同名文件算不算失败。**
   - 例：Water 删掉 `cache\index.dat`，应用马上又建一个，`cache` 就删不掉。
   - 总控推荐**不算**：只有“本该删、但原对象没删掉”才算失败；重建的新文件当成快照之后才出现的内容。
3. **自清理范围。** 总控推荐：
   - 只添加 `.worktrees`；
   - 离线依赖源先复制到 `.offline-cache`；
   - 工作树本身不删；
   - 回执与临时目录不在 M2。
4. **派单**：五张同时派，H4 交前端强的模型；执行者由你安排。
