# M1：用户可用的只读盘点版

2026-10-18，总控。M是Milestone（里程碑），M1为第一阶段“只读Alpha”；A–M是该阶段已经交付的模块工单编号，两种编号分别记录产品交付和模块验收。

M1的用户闭环：明确选择一个项目/受支持工具目录 → 查看扫描范围与覆盖/取消/错误 → 看对象类别、证据、保护原因和可信容量含义 → 生成默认不含凭证/正文的报告。没有删除、清理、prune或任意shell接口。仅受控样本和模块测试通过不能宣称整个闭环已交付。

## 当前缺口和推进顺序

| 用户需要 | 已有基础 | 尚缺与下一步 |
|---|---|---|
| 自己选择目录并盘点 | F/J只扫描受控夹具 | 原生目录/句柄身份 → 后端选择授权/范围注册 → 按句柄边界的有界元数据遍历 → 桌面选择器与取消闭环 |
| 看懂项目证据和容量 | L候选、M观察账本，已验收 | O将真实保留捕获及L/M实际输出展示在可操作页面；保留未知、冲突与弱证据含义 |
| 工具/对象分类与引用 | B官方事实包、L文件名候选 | 固定白名单的配置/marker内容读取、版本/结构与项目引用证据；不得依目录名降级保护 |
| 安全报告与完整用户流程 | H仅白名单汇总，K只读会话页面 | 详细脱敏报告的独立协议与确认范围、原生桌面接线、完整交互验收 |

N/O为本次两条独立外贴线：N只补Windows原生目录元数据/稳定身份检查基础，不授予扫描授权或遍历能力；O补L/M结果页面，不接N或真实目录。两条先独立交付，随后进入“目录选择授权+元数据遍历+交互服务”的纵向工单，避免继续只增加孤立计算模块。

N需要窄范围Win32 FFI，限定在单独native模块，逐处写SAFETY并实测当前Windows/文件系统；旧A–M的unsafe约束及冻结保持。仅允许冻结工具在N本树.local创建有界合成目录/文件/链接，Rust只读元数据；不扫描真实用户目录。句柄身份检查不等于授权、递归边界或TOCTOU保证，必须输出未授权/不允许遍历/竞态未验证标记。

O使用调用方内存bundle，展示保留J捕获与真实L/M输出；人工Unix身份例明确标合成内存样本，不冒称macOS或新扫描。无选目录、扫描、上传、删除或shell入口；新协议不修改K六字段冻结。

## M1放行口径

按需求W-F01–W-F07逐项验真实用户流程和明确授权的有界样本，不按模块数量宣布完成。先形成Windows可用闭环并单列证据，macOS保持未验证；M3才是两平台实机/打包Beta门。不会用等待macOS来推迟Windows功能闭环，也不会把Windows结果算作macOS通过。

这张计划不授权本机真实用户数据动作，不设置未经测量的发布日期。删除仍属M2、需独立执行器工单与验收。
