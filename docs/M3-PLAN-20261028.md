## 0. 一句话

M3 只做 Windows，分三块：
1. **认得更多**：本机这批 Agent 工具（Antigravity、Grok 多个家目录、Kimi Code、ZCode、OpenCode、WorkBuddy、Kiro、Qoder、Claude Code 原生安装等）留下的可清垃圾与必须保护的数据，都要在体检里出现。
2. **补齐 M2 的遗留**：宿主的关机保护、界面测试里剩下的无标记等待等。
3. **持续看护**（定时体检、泄漏提醒）等较大的功能，先由你定做不做、做成什么样。

## 1. 摸底：Agent 工具现在认不认得

现有 61 条规则里，Agent 工具只覆盖 Codex、Claude（Code 与桌面版）、Cursor、Grok（只认 `.grok`）。没登记的目录体检根本不扫，“未识别”里也看不到。

本机 10-28 只读摸底（只读名字、大小、时间），可清的候选：

| 候选 | 本机位置 | 本机体量 | 建议级别 | 依据 |
|---|---|---|---|---|
| 桌面版更新器残留（electron-updater） | `%LOCALAPPDATA%\*-updater\pending\*`、`*-updater\installer.exe`：Antigravity、ZCode、WorkBuddy、OpenCode 两代 | 约 1.5 GB | 推荐清理，24 小时 | 下载好的更新安装包，删了只会重新下载；electron-builder 源码与 issue #8730（安装后常不清理） |
| Agent 命令行自更新留下的旧二进制 | `~\.grok\bin\grok.exe.old`、`~\.kimi-code\bin\kimi.exe.bak` | 0.3 GB | 推荐清理，24 小时 | 名字就是备份；当前程序是同目录的 `grok.exe`、`kimi.exe` |
| Claude Code 原生安装的旧版本 | `~\.local\share\claude\versions\*`（2.1.285、2.1.287、2.1.296） | 0.5 GB（保留最新一个） | 推荐清理，保留最新 1 个，在用跳过 | 三个完整版本并排 |
| Cursor 编译缓存 | `%LOCALAPPDATA%\cursor-compile-cache` | 0.14 GB | 推荐清理，7 天 | 名字即缓存 |
| Qoder 工作区临时目录 | `~\.qoderworkcn\tmp\*` | 0.13 GB | 需要确认，1 天 | 文档没写；按工作区命名 |

| 多个家目录里的下载缓存 | `~\.grok*\.grok\downloads`（槽位家目录） | 待量 | 推荐清理，24 小时（同现有 Grok 规则） | 与 `.grok\downloads` 同一机制 |

更重要的是**看得见**：下面这些目前完全不显示，加成“受保护”后，体检会如实列出占用，但永远不可勾选。

| 受保护候选 | 本机体量 |

Grok 报告里标为“own knowledge, not verified”的进程名，写进规则之前要在这些程序运行时用进程快照核对一次。

## 2. 第六波：建议的票

目录互不相交，可以同时派。

| 单号（暂定） | 改哪里 | 内容 | 门 |
|---|---|---|---|
| **W6-I1 Agent 工具规则** | `packages/junk-rules` | 第 1 节的可清与受保护规则；通用 Electron 缓存补上本地的 `Code Cache`、`DawnGraphiteCache`、`DawnWebGPUCache`、`GrShaderCache`、`GPUPersistentCache`；数据版本加一 | 轻门；总控另做本机只读真实冒烟，核对每组命中的目录 |
| **W6-I2 宿主加固** | `apps/water/host` | 关机或重启时（`RunEvent::Exit`）也先停清理再退出；`app_state` 出错时按“可能在清理”处理，不放行关窗；关窗测试改成收到停止才会空闲；`\\?\` 断言真正走到比较 | 重门；总控另在真窗口里试“清理进行中关窗” |
| **W6-I3 界面加固** | `apps/water/ui` | 第 2、3 个测试开头的等待加标记、有界；重新连接在恢复成功后重读，并补读切页回来时仍缺的数据；补“去了又回来”与清理页“停止”的测试；过期提示条不再压住正文 | 轻门，截图 |

暂不排的小修（低级、方向安全）：清理执行器的十六进制键大小写折叠、帧间裸指针；服务写盘失败时的孤儿快照文件。留到下一波或与别的票合并。

检查器方面，总控要先做两件事：
- 让检查器认第六波清单；
- 给宿主整机检查加一个“清理进行中关窗”的步骤：先放一个大夹具，清理开始后关窗，核对窗口等清理停下才关、日志完整。

## 3. 较大的功能（各自要你定）

| 功能 | 做法选项 | 总控建议 |
|---|---|---|
| **定时体检与泄漏提醒** | a. 只在应用里提示“距上次体检 N 天”，并给出“按现在的增速，C 盘约几天后满”；b. 用 Windows 任务计划程序定时后台体检，有泄漏时弹系统通知；c. 常驻托盘 | 先做 a（纯界面与服务，风险小），b 留到 a 用过之后再定；不做 c |
| **原生工具命令**（`npm cache clean`、`uv cache prune`、`pnpm store prune` 等） | 由 Water 启动外部程序 | 暂不做。现有规则已能按目录清这些缓存；启动外部程序会放大安全面 |
| **会话归档**（把旧会话压缩存档后删除原件） | 动的是受保护数据 | 暂不做 |
| **孤儿进程**（会话结束后残留的 node、浏览器子进程） | 只列出：占多少内存、由谁留下 | 可以排在第七波，只列不结束 |
| **签名分发** | 需要代码签名证书（要花钱） | 留到 M4 收费验证时 |

## 4. 要你拍板

1. **第六波范围**：I1、I2、I3 三张同时派（推荐）；还是只先做 I1。
2. **Agent 工具规则的级别**：按第 1 节（更新器残留、旧二进制、Claude Code 旧版本为推荐清理；Qoder 临时目录为需要确认）。
3. **不再使用的 Grok 槽位家目录**（`.grok1`～`.grok3`，你说已退订或停用）：
   - 推荐：和别的会话一样受保护，只显示占用，要删你自己删；
   - 另一个选择：整目录列为“需要确认”，可以在 Water 里勾选删除（会连同里面的会话与登录凭据一起删）。
4. **定时体检与提醒**：先做应用内提示与“几天后满”（推荐），还是直接做任务计划程序的后台体检。
5. **原生命令、会话归档、孤儿进程、签名分发**：按第 3 节的建议放。

拍板后：总控先改检查器、写规则契约与三张票，跑检查器自检与派前 baseline，再给派单句。规则票的调研与核对可以继续交给 Grok 做初稿，总控在本机核实后定稿。
