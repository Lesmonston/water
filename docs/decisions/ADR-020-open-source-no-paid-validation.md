# ADR-020：开源项目，不做收费验证

2026-11-07，总控（Claude）。修订[立项书](../PROJECT-CHARTER.md)“成功与停止条件”里的商业假设、[开源策略](../OPEN-SOURCE-STRATEGY.md)的“商业方向”，以及[路线图](../ROADMAP.md)的 M4。

**状态**：方向已由用户定（11-07）。许可证、公开方式与仓库名待定，见[到开源发布的整体计划](../PLAN-OPEN-SOURCE-20261107.md)第 6 节。

## 用户原话

- 2026-11-07，看了以收费试用为终点的整体计划草稿：“不需要收费验证啊，目前我这个是规划开源项目”。

## 决定

1. **M4 收费验证取消**，下一个里程碑改为**开源发布 v0.1**。
2. 不做授权检查、收款、价格与付费功能，也不再按“免费 / 付费”划分功能。
3. 立项书里的价值门槛（误判、腾出空间、清完后是否耽误工作）仍然有用，改为开源发布后从 issue 与使用反馈里看，不再和付款挂钩。
4. 开源策略里“独立实现、不复制上游源码与规则”的做法不变；Mole（GPL-3.0）仍只作阅读。选许可证时要核对全部依赖的许可证。

## 影响

- 立项书、开源策略里关于收费的段落以本文为准，原文留作历史。
- 安全底线不变：保护资产零误入默认清理、先预览再由用户本人按、隔离区可还原，这些不因开源而放宽。
- 发布前要做的“公开仓库”工作见整体计划第 3 节：现在的私有仓库带有大量验收证据、本机用户名与个人邮箱，不直接公开。
