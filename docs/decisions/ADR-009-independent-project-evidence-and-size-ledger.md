# ADR-009：K补单期间独立推进项目证据与容量账本

2026-10-18，采纳。用户已要求将并行评估落实成正式外贴工单。K补单继续原树/分支/基线/helper/132冻结；总控准备L/M新树，不启动内部实现者。

L从已验证facts提取四种Node/Python文件名标记候选，固定filename_only/未核格式/保护，不修改B工具事实包或G/J旧报告。M对同一受控观察集合记录逻辑长度、已知身份分组、Unknown和冲突，不推断卷唯一空间或回收量。两线只依赖已验收A/G及冻结内存输入，互不依赖，也不依赖在途K页面。

新输出为独立侧车，完整来源facts/totals保留；现有类别unknown、风险protected和来源容量未知不变。新sum允许u128十进制字符串，但不能写回A的u64 ByteCount协议。Windows Unknown身份与人工Unix样本分开，算法通过不代替macOS采集。

两票各独占产品目录、workspace/锁、Cargo home/target/tmp和证据；无物理fixture/真实用户目录/内容读取/浏览器/执行器权限。只用旧依赖缓存离线构建，jobs1/一次一个门。新增helper保存完整红/恢复与源码字节，按Cargo实际构建图选择产物，避免同名旧rlib干扰；旧helper/锁不改。

总控先冻结SPEC、完整golden、原始错误、测试名、桥接与范围锁，再实际验证已验收A/G可接受全部输入、工具链及独立树baseline；全部通过才标READY给用户外贴。预检不运行尚不存在的L/M产品。收单分别验收，后续页面/桌面/真实scope接线另票，不因侧车增加而改K补单或开放删除。
