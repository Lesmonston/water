# ADR-007：F/G/H/I并行推进

2026-10-17，采纳。用户明确要求一次安排多张可并行任务。继续由总控冻结、用户外贴实现；不自动启动实现worker。

F的扫描实现继续原树/原票/22锁。新增G报告组装、H白名单汇总导出、I报告阅读界面，分别独占g/h/i树和目录。G只依赖已验收A/E和冻结的F JSON事实协议，不依赖尚未实现的F crate；H只依赖A；I只依赖E输出及已安装Node/Chrome。测试输入全部为总控合成材料，不假装已发生F扫描或真实平台IO。

G返回报告及完整source_facts sidecar：A没有identity/kind/depth/origin/operation槽位，不能扩展旧DTO或丢失来源。G全部未知/保护、总容量未知，是保守报告组装，不提前推断缓存或可删对象。H从经A验证的报告构造固定白名单汇总，不含ID、路径或自由文本；精确容量及分布仍可能关联，不称为不可关联匿名。I读取真实E投影生成的冻结合成报告，切换整份报告；不使用旧C演示协议、不接真实文件/IPC。

三票自有workspace或零依赖Node目录，不改根Cargo、A–F、旧helpers/冻结/分配。新共享parallel-next锁只冻结总控材料；工人改动目录与报告/证据互不相交。G/H用私有Cargo home/target/tmp，I用自己的Chrome profile和loopback临时服务；不安装依赖。每条线同时一个检查，F/G/H可各自构建一次，I只开一个浏览器，不启动整仓/watch/coverage。

F→G真实扫描链路及G/H/I跨模块集成由总控在各票验收后进行；接口不兼容发编号补单，不允许工人互相修改或合主线。真实用户scope、生产竞态防护、工具分类、去重计量、Tauri壳、macOS实机和发布仍独立规划，不从本批派单推导授权。
