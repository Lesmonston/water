# ADR-003：与A并行的规则包及交互原型

日期：2026-10-17。状态：采纳。用户请求检查可并行任务。

W1-A依赖的扫描器/分类器/正式桌面集成仍等待A验收，但工具发现事实包与独立交互原型可各自交付、独立验收。因此本轮增加B/C两条工作线，各用独立工作树，不改A已冻结文件、基线、权限或Cargo目录。

此决策追加扩展ADR-002中的“初始本轮只发A”排期，不修改其冻结文本或A票的实现权限。A的workerRules/helper/contractLock默认字段保持原值；B/C使用任务级的另一套rules/helper/lock，不继承Rust单的专属限制。

- B：机器可读六工具发现/保护数据、独立Node校验及测试。事实来自官方文档，不扫描本机、不产生清理动作。
- C：虚构数据驱动的只读交互原型与真实浏览器检查。不连接Rust/Tauri，不用作“实际清理已实现”的证明。

总控先冻结各自的独立协议与演示fixture；实现由用户外贴。当前A有工程文件写入证据，总控不更改其工作树或冻结锁。

后续接入需要单独任务：B数据由Rust适配器读取前重新版本核对；C交互在Tauri接线前做数据边界与安全复核。本轮不承诺将Node校验器或演示数据直接发布为产品内核。

本机Node24与既有Chrome可用，B/C不安装npm或浏览器依赖。当前工具UI不适用面向落地页的design-taste-frontend，因此采用本项目的工具界面验收要求，而非套用其hero/营销布局规则。
