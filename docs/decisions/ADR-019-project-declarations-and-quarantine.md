## 1. 读项目清理声明 `.water-cleanup.json`（已拍板）

Water 只靠名字和结构推断，F1、F2 这类误判会一直有；项目自己声明“这些能清、这些不能碰”最准。ADR-015 有先例：用户同意后只读所选根目录的 `package.json`，并把“读了内容”与元数据分开标记。本条照这个先例放宽，只放宽到这一个文件。

1. **只读这一个名字**，只在用户加的位置的根目录与往下 4 层以内找；固定的系统位置不找。文件不超过 64 KB，按 JSON 解析，从不执行。只有 `packages/cleanup-manifest` 读它；读过的内容在记录里与元数据分开标记。
2. **首次信任**：发现新的声明时，界面列出它的条目，用户点“信任”才按它的“可清”生效。信任绑定文件内容的哈希，文件一改就要重新确认。
3. **`protected` 永远生效**，不信任时也生效（只会让 Water 更保守），任何规则都不能清它列的路径。
4. **`disposable` 只在声明所在目录之内**：相对路径；不允许 `..`、绝对路径、盘符、单独的 `*` 或 `**`；不跨联接；不碰 `.git` 目录。Water 原有的保护全部照旧：受保护类别、在用检测、年龄、贵重件名、清理前逐项复核。
5. **条件只有固定几种**：`always`、`older-than-N-days`、`sibling-complete-file-exists`；`keepNewest` 保留最新 N 个；`ask: true` 为“需要确认”，否则为“推荐清理”。
6. **只显示、不执行的字段**：`producer`、`fixedIn`、`worktrees`。Water 不跑 git、不执行命令，也从不写或改这份文件。
7. 格式不对的整份忽略，界面写出原因。

## 2. 读工作树 `.git` 小文件的 `gitdir:` 一行（已拍板）

用来区分“登记有效的工作树”与“已脱离 git 的目录”（`denglou` 有 11 个、约 11 GB，其中一个里有被 git 忽略的正式签名副本）。

- 只读名为 `.git`、且是**文件**（不是目录）、不超过 1 KB 的那一个；只取第一行 `gitdir: ` 后面的路径，只用来查这个路径在不在。
- 不读 `.git` 目录里的任何东西，不跑 git。两类都仍是“仅供参考”；已脱离的写明“git 查不了有没有未提交的东西”。

## 3. 先隔离，再删除（已拍板，修订 ADR-018“删除不进回收站”）

这一轮总控清理一直是先移到同盘隔离目录、用户核对后再删，没有误删到无法挽回的（E5 的两个工程 zip 在删之前都还能取回）；唯一的损失（`yb-release` 的签名副本）恰恰发生在隔离区被删之后、而且没有逐文件清单。

1. **需要确认的组、泄漏簇、项目声明的组**清理时移到同盘 `<盘>:\.water-quarantine\<清理编号>\<原路径>`。只做同卷改名；不能同卷移动的项跳过并写明原因，绝不跨盘复制。
2. **推荐清理的缓存**照旧直接删除，空间立刻腾出。确认框写明两部分各多少，以及“隔离的部分要等你永久删除后才腾出空间”。
3. **隔离区**：列出每次清理的条目（原路径、大小、时间、规则，以及条目里认出的贵重件文件名），可以还原或永久删除。永久删除由 Water 的执行器做：不跟联接、只删联接本身、能处理保留名与结尾点或空格的名字。原位置已有内容时不覆盖还原。
4. **不自动删除**：放满 7 天提醒一次，由用户决定。
5. Water 扫描时不把自己的隔离目录当垃圾。
6. 移到隔离区之前的复核与删除相同（仍在规则根内、仍匹配规则、年龄、不是联接、未被占用、身份一致），另加：不是别处联接的目标。

执行器的移动、还原、永久删除按**重门**：有效负控、原字节恢复、总控独立复核。

## 4. 界面

界面设计以 [`docs/design/water-ui-v2/`](../design/water-ui-v2/DESIGN.md) 为准（布局、导航、按钮、菜单、交互）；材质、颜色与品牌沿用 v1。ADR-018“界面设计”一段里的设计稿位置随之改为 v2。界面仍只提交 ID、决定与确认令牌，从不提交或拼接路径；选择状态由服务计算，界面只显示并转交用户的决定。

## 5. 会话记录可由用户选择清理（待拍板）

Kimi Code 试验（10-29）：整体清掉一个少用工具的历史会话后，工具照常使用，代价只是历史会话不能再续接或回看。若用户拍板：

- 设置里按工具一个开关“允许清理 N 天前的会话”，默认关；
- 打开后旧会话作为“需要确认”的卡片出现，清理时一律先进隔离区；
- 工具正在运行、会话文件还在写入的，一律跳过；
- 界面写明代价。

不改写会话内容（“剥图瘦身”不在此列）。

## 6. 读已安装程序的列表（待拍板）

用来认出卸载后留下的应用数据（如 MiniMax Hub 的 `@hilo`，1.21 GB），以及“软件已经装好、安装包还在”。若用户拍板：只读注册表里已安装程序的显示名称、版本与安装位置，不读其它注册表项，不读这些程序的文件内容。

## 不变

- 除第 1、2 节的两种文件外，不读任何文件内容；
- 受保护类别（会话、浏览器登录数据、项目仓库、未知数据库）不可清，第 5 节拍板后只对用户打开的工具例外；
- 不提权、不改系统设置、不结束进程；
- 真实删除只经 Water 应用自身的清理流程、由用户本人按下。
