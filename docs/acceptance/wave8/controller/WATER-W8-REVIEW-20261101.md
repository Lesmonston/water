## 遗留

K3：
1. 大小与修改时间取自目录项，对正在写入的文件可能滞后；与清理执行器的复核同口径（见上）。
2. 非 NTFS 文件系统（exFAT、FAT32、部分网络盘）可能不支持信息类 19/20，每个目录都会记 `access_denied`。清理执行器同样依赖它。本机四个盘都是 NTFS。**K4 规定盘根只接受 NTFS/ReFS 固定盘**。
3. 停止时只有当前帧的 target 记 `budget_exhausted`，同根其它组可能缺这条 issue；清理闸门对任何 `budget_exhausted` 都拒绝，安全不受影响。
4. 去重用的文件 ID 集合随项增长，约每百万文件 45 MB；每个目录分配并清零 64 KiB 缓冲区，还多一次取卷序列号。
5. `result_from_json` 先解析成 `Value`，重复的 JSON 键不再报错（服务一侧本来就先解析成 `Value`）。
6. 一次遍历的测试拿新代码单独跑与合跑相比，不是与旧实现相比（总控夹具与审查读代码补上了等价性）；真实计划里没有 marker 目标，marker 路径还没在真实数据上跑过，留给第五次整合检查。
7. 根路径只差大小写时，命中路径用第一个 target 的写法。
8. 测试缺口：c6（`eligible_unique_bytes` 补值来源）、c10（测量途中的 issue 重放）没被抓到。
