### 7.3 新发现（高级）：Windows 自带的兼容联接让用户目录整片不可清

这次常用位置体检里，**214 项**的不可清原因是“被 `C:\Documents and Settings` 引用，改指别处后可清”。连 `npm-cache`、`chrome-cache` 这些老规则也被拦下。

- **原因**：`C:\Documents and Settings` 是 Windows 自带的兼容联接，指向 `C:\Users`；每个用户目录里还有 `Application Data`、`Local Settings` 等同类联接。
  - 扫描把联接都放进“引用”索引；
  - 第十波的契约（[SCAN-M35](../../../../contracts/m35-v1/SCAN-M35.md) 第 247 行）规定，联接的最终目标“等于条目、位于条目之内或**包住条目**”都算引用。`C:\Users` 包住了用户目录下的每一个条目，所以全部算“被引用”。
  - 代码在 `packages/junk-scan/src/scan.rs` 第 1186 行一带，照契约实现；自第十波（`567f0283`，11-05）起就是这样。
- **以前为什么没发现**：
  - 测试夹具里没有系统兼容联接；
  - 第八到第十次的同位置复验只看 D 盘和 `F:\Mirasim-A`；
  - 服务与规则的真实冒烟只报计数。
- **影响**：
  - 方向是少清，不会误删；
  - 但在任何一台 Windows 的 C 盘上，用户目录下本来能清的缓存与日志都会被拦下。结论页看起来正常（“可以放心清理”，可清的多是 `Windows\Temp`），用户不会知道少了什么。
  - 开源发布前必须修。
- **这是总控写契约时的漏项**：没有想到系统自带的兼容联接。
- **修法要改契约，再出单**。总控建议两条一起做，由用户定：
  1. 建索引时不收 Windows 自带的兼容联接（这类联接带“隐藏 + 系统”属性）；
  2. 只认“指向条目本身或条目里面”的联接，不再认“包住条目”的——一个指向大目录的联接，不等于依赖目录里某个缓存。
- 修好后，用常用位置体检再复验一次，看新规则的可清量。
