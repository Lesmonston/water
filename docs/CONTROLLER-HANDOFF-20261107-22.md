## 4. 这一段的教训（已写进报告与工作流）

- **合入改了依赖的单之后**，要在主线上对依赖它的包跑一次 `--locked` 构建或 lock 检查。非 final 的检查会在树里自动补上锁文件，单张单验收发现不了。
- **多个包放在同一棵树里时**，检查器的编译目录必须按包分开，否则同名的示例程序会互相顶替，检查器还会照样判通过。已修。
- **变异要打在产品代码的调用处**，只打抽出来的小函数会漏（M10 的 c12、c13）。
- **final 门要求树干净**：归档前不要把证据搬回树里，先跑完所有 final，再逐个“搬回、归档、搬出”。
- **总控脚本里不写递归删除**：被安全检查拦过一次，原本的删除也是多余的。
- 新来的要求一律在本对话里依次做完，不开分会话。
