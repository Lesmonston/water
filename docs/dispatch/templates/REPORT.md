# 回执模板：不可直接作为完成声明

第一行由执行者选择且填写真实值：

```text
<票号>[ 补充单N] 任务已完成，任务报告在 <本报告绝对路径>
<票号>[ 补充单N] 任务受阻，任务报告在 <本报告绝对路径>
```

## 身份与版本

票面路径、工单/补单号、工作树、分支、完整基线、实际实现SHA、报告/证据SHA；实际引擎和模型。若存在允许的只读辅助，写明数量与任务。

## 交付状态

实际完成、未完成、受阻原因、保留的未提交文件。逐项对照INV，引用实际文件与入口；根因事实与假设分开。

## 变更范围

实际改动文件；冻结契约是否变化；依赖/配置是否变化；既有断言每项改前、改后、理由及票面授权。越界需求必须报告，不能先改再解释。

## 检查记录

每条命令、cwd、测试文件/用例名、开始与结束、退出码、原始汇总和日志路径、测试时实现SHA。不得把未运行的平台写通过；skip、超时、部分失败及重跑原样记录。

## 负控与恢复

仅适用的行为/安全任务填写：真实逻辑改动、命令和失败的具体断言、退出码、修改前/改坏/恢复哈希、最终定向门结果。运行失败而非目标断言失败要标无效；无负控要求的任务说明不适用。

## 剩余风险与需要总控处理

未验证平台、无法执行的检查、票面遗漏、最小补充需求。不把受阻请求直接交用户作权限裁决。

## 提交后状态

实现SHA与最终测试关系，报告提交是否仅文档证据，git状态和自己启动的进程退出情况。提交后若改了产品代码，重新测试并报告新SHA。停止修改，等待总控收单；不得自写“已验收合入”。
