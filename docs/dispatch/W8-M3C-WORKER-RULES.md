## 2. 写代码

- 契约、检查脚本、台账也不能改。契约冲突或缺东西时写受阻回执，不要自行变通。
- **公开接口**只按 SPEC 增加，不改动、不删除原有的。

- **旧断言**：只有 SPEC 写明“获准修改”的才能改，并在回执里逐条写出原值与新值；其余原有断言与标记不变。SPEC 没想到、但因本单改动而必然要改的旧断言：**先写受阻回执**，不要自行改。

## 3. 夹具与真实数据

- 合成夹具只能建在本树 `.local/` 下：
  - 每次用随机名新建一个目录；
  - 测试结束**只删除本次新建的那一个目录**（校验父目录与名字前缀）；
  - 不得递归删除任何别的东西。
- K1 的测试会把 `C:\Windows\System32\PING.EXE` 复制进本次夹具目录并从那里运行。测试结束只结束自己启动、命令行含本次令牌的进程，并复核为空。
- K3 的硬链接夹具用 `cmd /c mklink /H` 建，不需要管理员；不创建符号链接。
- **真实数据**：
  - K1、K2 的 `--mode real` 只读本机进程列表或已知目录是否存在，输出只有计数；
  - K3 的 `--mode real` 是一次只读真实扫描，只输出组级汇总，不含路径；
  - 都不读文件内容，不清理。
- **K5 的整机检查**与第七波 J1 相同：
  - 检查器在本树 `.local/w8-k5-native/` 下生成夹具，七个分类全部关闭，只清理夹具；
  - 原生窗口只有这 1 个（`native --final`），选择框 0。
- K6 的浏览器测试只开一个私有 headless Chrome。

## 4. 检查与负控

| 模式 | 作用 |
|---|---|
| `lock` | Rust 单：锁文件已存在，只核对依赖 |
| `check` | 依赖与源码政策、`cargo fmt --check`、`cargo clippy -D warnings`；K6 为语法检查与界面政策 |
| `test` | 跑工单指定的测试（K6 为单元测试），名字与数量必须完全一致 |
| `browser` | K6 的浏览器测试与截图 |
| `real` | K1、K2、K3 的只读真实冒烟 |
| `native` | K5 的夹具清理闭环，只作为 final |
| `red-nc1` 等 | 有效负控 |
| `archive` | 把 `.local/checks/<单号>/` 的回执、日志与截图按原字节复制进证据目录并写索引 |

负控做法：
1. **只改生产代码里真正被调用的那一处**，不改测试、不加开关。检查器只认生产源码目录下的改动：Rust 单是各自包的 `src/`，K6 是 `apps/water/ui/` 下的产品文件（只改规则数据不算）。
2. 运行 `--mode red-ncN`，它必须以目标标记失败。
3. **立即**用 `git checkout -- <文件>` 恢复原字节，跑一次 `--mode test` 变绿，再做下一条。

检查器会核对源码哈希。下面这些红不算数：
- 用编译错误、超时或改测试造出来的；
- 别的测试先超时、或先撞上旧标记失败的。
遇到这种情况，要换更窄的改动位置。

**机器上同时有五张单在编译与测试**，磁盘可能很忙：
- 私有 Chrome 若在编译时失去响应，可以原样重跑一次 `--mode browser`；
- 进程或扫描测试偶发超时，可以原样重跑一次；
- 连续两次失败就停下写受阻回执。

## 5. 收尾

1. 实现与测试全部提交，得到干净的实现提交。
2. 在这个干净提交上依次跑工单列出的 final。final 会核对负控记录；产品字节不变时不要重复跑。
3. 跑 `--mode archive`，写回执（路径见工单），把回执与证据目录逐个文件 `git add` 后单独提交。
   - 后续提交只能含回执与证据（包括归档器生成的 `.gitattributes`）；
   - 证据里的 `.log` 若被忽略，用 `git add -f`。
4. 回执第一行与给用户的通知完全一样：`<单号> 任务已完成，任务报告在 <绝对路径>`；受阻则写“任务受阻”。
5. 回执必须写清：
   - 实际模型；
   - 实现提交 SHA；
   - 逐条对照 SPEC；
   - 每个检查命令与结果；
   - 负控：改了哪一处、失败信息、恢复后的哈希；
   - 改过的旧断言：原值、新值；
   - K5 的整机步骤、用时、退出码与截图；K6 逐张截图写看到了什么；K1、K2、K3 的真实冒烟结果；
   - 没做或没验证的事。

**提交身份**：本机没有配置 git 身份，也不许改配置。只在提交命令的进程里设 `GIT_AUTHOR_NAME`、`GIT_AUTHOR_EMAIL`、`GIT_COMMITTER_NAME`、`GIT_COMMITTER_EMAIL`，用**执行者自己的名字**（如模型名）与 `<名字>@localhost` 这类地址。**不要借用仓库里已有的人类作者身份。**

**远端与历史**：
- 不 push 到任何远端，不添加或修改 git 远端与配置；
- 不改写已有提交（不 amend、reset、squash、rebase 或任何强制操作），只在首次 HEAD 之后新增提交；
- 提交信息写错就在回执里说明，不要改写。

禁止：merge、`git add -A`、`git clean`、`git stash`、改主线台账、提交别人的文件。交回后停止一切测试与后台进程。
