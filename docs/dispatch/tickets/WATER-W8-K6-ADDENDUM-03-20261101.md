## 要做的（全部在 `apps/water/ui/`）

### 1. 跳过、恢复成功后重读结果（高）

**问题**：`restoreSkip` 只更新位置列表，结果页、操作坞、缓存的详情都不重读。在新服务下：
- **会话里先跳过、再恢复**：
  1. 已选组 G 里对 X 点“以后都跳过”。重读的详情把 X 列为 `user_skipped`，`rememberDetail` 按补单 02 删掉 X 的排除。
  2. 到“位置”点“恢复”X。服务立即让 X 可清理，界面什么都不重读。
  3. 回结果页点“清理所选”，`clean_prepare` 没带 X 的排除，服务把 X 放进计划。但组行、操作坞、缓存的抽屉都还按“已设为以后都跳过”或不计入显示。
- **扫描前就跳过的项**：勾选它所在的组，到“位置”恢复它，回结果页清理，这一项会被删除，而它在界面上从来没显示为可清理或已选。如果所在的是默认选中的推荐组，用户不勾任何东西也会命中。
- `skip_add` 也只替换一个组：结果页的“可放心清理”、图例、分类合计、按盘推荐、首页上次体检的数字，都还带着已跳过的体量（只影响显示）。

**改为**：
- `skip_add` 或 `skip_remove` 成功后，如果当前有结果、仍是同一次扫描、没有过期，就用同一个 `scan_id` 重读 `scan_result`：
  - 替换 `state.result`，**保留当前选择**（不要走新扫描的整体重置）；
  - 清空详情缓存（`state.details`）；要保留的排除仍按条目 ID 保留，对服务仍然有效。
  - 首页“上次体检”的数字也按重读结果更新，或者下次进首页时重读。
- 重读完成之前，“清理所选”不可点，可以沿用现有的进行中状态。
- 重读失败，或回应到达时已不是同一次扫描，就把当前结果标为过期，沿用现有的过期提示，要求重新体检。不要在数字可能不对的情况下允许清理。
- 恢复成功后，被恢复的项按服务的新状态显示：组已选时，它算进这一组的项数与体量，操作坞跟着变；它在重读后的详情里显示为可清理、已勾选。这样操作坞始终等于“清理所选”真正会清理的范围（补单 01 第 2 条）。
- 恢复成功的提示改为说明这一点，例如：“已恢复，这一项重新算进可清理的范围”。具体措辞你定，不用 emoji。
- `skip_add` 成功后先在本地排除这一项（补单 02 第 3.2 条），不变；之后的重读与抽屉重绘照上面执行。

**假宿主**（只在 `tests/`）：
- 加一个开关，模拟新服务：`skip_add` 让该项不可清理、扣合计与组数；`skip_remove` 恢复扫描时的状态；`scan_result` 与 `group_detail` 都反映当前跳过名单。
- `clean_prepare` 收到属于已跳过项的排除 ID 时，照补充 01 第 3 条接受并忽略，不返回 `invalid`。

旧服务开关保留，现有断言照常跑。

### 2. 低级

1. **切页后跳过失败**：`skip_add` 请求进行中切走页面、请求随后失败时，错误目前被吞掉，用户以为已经跳过，这一项仍在清理范围里。改为在回到结果页或全局提示里说明“跳过没有成功”，或者至少保证这一项保持原来的勾选状态并给出提示。具体做法你定，回执写清楚。
2. **打开中的抽屉不重绘**：在同一个抽屉里排除掉组里最后一个可清理项后，抽屉里的勾选框仍可操作，再勾回一项就把组重新纳入，与补单 02 第 3.1 条“只能在结果页重新勾选这一组”不符。改为条目勾选变化后抽屉随之重绘，或者至少刷新勾选框与提示行。
3. **级别筛选下的“已选 X”**：分类标题下的“已选 X”仍包含被级别筛掉的组，会出现全选框未勾、旁边却显示“已选 1.0 GB”。改为与全选框同一口径：只算当前视图里看得到的组（级别筛选与盘筛选的交集，盘筛选时仍按该盘的量）。
4. **没有选中时的“已选 <1 MB”**：例如全部是受保护组的“未识别”分类，或一个组都没选的分类，标题下显示“已选 <1 MB”，像是选了一点东西。分类里没有选中的组时，不显示“已选”这一行。
5. **过期抽屉的提示**：结果已过期时，抽屉里仍提示“先在结果页勾选这个分组，才能逐项排除”，但过期时结果页不能勾选。过期时不显示这句，或改为提示需要重新体检。
6. **位置页说明句**：`views/locations.mjs` 里那句说明末尾缺句号，补上。
7. **测试**：
   - `tests/browser.test.mjs` 里直接读 `document.querySelector("[data-key=item-i-000201]").disabled` 那一处，元素缺失时报“Browser expression threw”，不带标记。改成先判断元素存在，缺失时失败信息带原标记（与补单 02 第 4 条同一类）。
   - “点被禁用的勾选框不会选上组”那条浏览器断言实际上不可能失败（禁用的勾选框不触发 change）。可以保留，但回执里说明真正的保证在单元测试；也可以改成直接派发 change 事件来验证。
