## 1. 要做的

### 1.1 三份样例换成虚构路径（W13 第 4.1 节）

**要换掉的**：

- 盘根下 `new` 目录里的路径（本机的工作目录，以及本机其它项目，有的写在路径里，有的写在线索文字或 ID 里）；
- `C:\Users\` 下的真实用户名；
- 一个真实软件名，以及它的安装目录与安装包名；
- W13 第 0 节列的其它内容。

**怎么换**：

| 原值的类别 | 新值 |
|---|---|
| 工作目录（本项目） | `D:\code\flick` |
| 本机其它项目 | `D:\code\<通用名>`，如 `demo-app`、`server-kit`、`engine-lab`、`audit-tool`、`ui-kit`、`video-lab`，一个项目一个名字 |
| 用户目录 | `C:\Users\alice` |
| 那个真实软件 | `Acme`（目录、安装包名照这个改，版本号可以换成 `1.2.3` 这类） |

- 同一个原值在三份里换成同一个新值，包括出现在 ID（如线索 ID 里带的项目名）、线索文字、复制文字、显示路径里的。
- JSON 里的反斜线照原来的转义写法。
- **键与类型一个不改**：
  - 只改字符串的值，数组长度、数字、布尔、null 都不动；
  - 服务的测试也读这三份，只核形状。
  - 改完后写一个一次性的比对（不入库也可以），把三份按键与类型逐层对照基线版本（`git show <基线>:<文件>`），回执里写比对结果“键与类型完全一致”。
- **回执里的映射表**只写“原值的类别 → 新值”，不写原值本身。
- 换了路径后，长度、截断、排序可能变：照新样例改测试里依赖具体文字的断言（获准，见第 2 节），截图全部重拍。
