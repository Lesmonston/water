## 要做的（全部在 `apps/water/ui/`）

### 1. 手工排除的项，跳过再恢复后仍然排除（中）

**问题**：
1. 已选组 G 有 A、X 两个可清理项。用户在抽屉里取消 X，组仍是半选。
2. 用户再对 X 点“以后都跳过”。
3. 重读详情时，X 被列为“已设为以后都跳过”，`rememberDetail` 把 X 移出排除集合。
4. 用户到“位置”恢复 X。重读后 X 重新可清理、所属组仍选中、不在排除集合里，操作坞多出这一项，`clean_prepare` 会让服务删掉 X。用户本次明确取消过它。

如果 X 是组里最后一个，组会被移出选择（补单 04），X 不会回来；组里有别的项，X 就会回来。两种情况不一致。

**改为**：
- 区分两种排除：
  - **跳过保险排除**：补单 02 第 3.2 条，跳过成功后自动加的；
  - **手工排除**：用户在抽屉里取消勾选的。
- `rememberDetail` 修剪时：
  - 对“明确不可清理”的项，只去掉**跳过保险**排除；
  - 手工排除保留，扫描时就不可清理的项照旧处理；
  - 做法你定，例如在跳过前记下这一项是否已被手工排除。
- 保留下来的手工排除 ID 可以照常放进 `excludeItemIds`：真实服务对属于已跳过项的排除 ID 接受并忽略（不计 `excluded_count`），假宿主也一样，不会触发 `invalid`。
- 操作坞与项数：已跳过的项不重复扣除（`excludedItems` 只算可清理项，现有规则）。恢复后它重新可清理且仍被排除，操作坞不算它。
- 没有事先手工排除、只是跳过再恢复的项，按补单 03 处理：重新算进所在的已选组。

### 2. 低级

1. **抽屉里当场跳过失败的提示**：补单 04 改成“后来的错误优先”之后，在抽屉里当场跳过失败时，提示条显示的是服务原文（例如名单满 64 条时显示“所选内容无法清理，请重新选择。”），不再是跳过专用的说明。在 `skipItem` 的失败分支里，把错误文案换成跳过专用的说明再抛出，例如“跳过没有成功，这一项保留原来的勾选状态。”。
2. **条目被禁用后的焦点**：现在焦点会移到同一行的“以后都跳过”。键盘用户按空格取消最后一项后，再按一次空格就会误写一条持久的跳过设置。改为把焦点放到说明行（`tabindex="-1"`，并加 `role="status"` 让读屏软件播报原因）或关闭按钮，不要落在会写设置的按钮上。说明行插入时，尽量不让正在滚动的列表跳动。
3. **设置类调用的结果不明时一律过期**：`skip_add`、`skip_remove`、`locations_set_category` 失败时，服务可能已经生效（例如宿主断连）。当前有未过期的结果时，这三类调用一旦失败，就把结果标为过期，与重读失败同样处理。
4. **假宿主的 skip ID**：真实服务取最小空号，删除后会复用。假宿主照此改，断言改为“当前条目之间不重复”，回执写原文。
5. **README**：更新到补单 04、05 的实际行为：抽屉原地更新、排空的组移出选择、切换分类开关后重读、新的恢复措辞、手工排除的保留规则。
6. **测试强度**：
   - 补单 04 第 2.1 项的两处修复要各自有断言能单独抓到：一是“后来的错误优先显示”，二是“开始清理时清掉跳过失败的提示”。例如在跳过失败提示还在时，让一个非清理操作出错，断言显示的是后来的错误。
   - 调用处把保留的排除元数据传给 `setItemSelected`，加一条浏览器层面的断言。
