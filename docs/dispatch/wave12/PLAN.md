## 1. 整组、整行“以后都跳过”

### 1.1 现在的样子

- 只能跳过**单个条目**：`skip_add {itemId}`。服务记下这一条的路径，以后扫到**完全相同的路径**就判为不可清理。
- 判断卡和抽屉里的汇总行，“⋯”里都没有“以后都跳过”。第十波 M6 补单 02 把它们先藏了起来，因为当时没有对应的接口。
- 跳过名单最多 64 条。

### 1.2 要做成什么样

| 在哪点 | 记下什么 | 以后怎样 |
|---|---|---|
| 判断卡“⋯ → 以后都跳过” | 这张卡的组。组 ID 已带“位置 + 规则”，如 `custom:drive-d:python-tool-caches`；泄漏簇是 `leak:` 加父目录与模板的哈希 | 以后每次体检，这个组里的可清项都判为“已设为以后都跳过”，**新长出来的也算** |
| 合并卡（一张卡跨几个位置） | 卡里每个位置的组，一次全记上 | 同上 |
| 抽屉的“同模板”一行（如 `verify-****** × 81`） | 组 + 模板 | 这个组里符合这个模板的条目，以后都跳过 |
| 抽屉的“同一父目录”一行 | 组 + 父目录 | 这个组里直接在这个父目录下的条目，以后都跳过 |
| 抽屉的“其它 N 项” | 不提供 | 太杂，跳过了也说不清跳过的是什么 |
| 单个条目（现有） | 路径 | 不变 |

- **为什么能按组记**：总控拿第八次和第九次两次真实复验的扫描记录比过。两次相隔 6 小时、用的是不同版本，48 个组 ID 全部相同，4 个泄漏簇的 ID 也相同。
- **一次点击算一条**：跳过名单的 64 条上限不变。合并卡跨 3 个位置时算 3 条，名单放不下就整次不记，返回 `invalid`，不会只记一半。
- **绑定结论版本**：命令带 `conclusionVersion`。结论过期时返回 `stale`，和“清理/保留”的选择一样。这样汇总行的 `r:` ID 不会指错。
- **立刻生效**：和单条跳过一样，最新一次体检里马上扣掉，不用重新体检。
- **跳过名单页**：每条写清楚是什么，如“Python 工具缓存 · D 盘”“`verify-******` · 某目录”“这个文件夹本身”，旁边是“移除”。移除后下次体检恢复。
- **级别**：只有“推荐”和“要确认”的组能跳过；受保护与仅供参考的本来就不清。

### 1.3 接口（写成冻结契约 `contracts/w12-v1/`）

- **新命令**：`skip_unit_add {conclusionVersion, unitId}`，`unitId` 是卡片 ID 或抽屉行 ID。另起新命令，原来的 `skip_add {itemId}` 逐字节不变，新宿主配旧服务时单条跳过照常能用。
- **设置**：`skipped` 每条加 `kind`（`path` / `group` / `template` / `folder`）和显示用的文字。设置版本加一，读旧设置时旧条目都是 `path`。
- **位置页**：`Locations.skipped` 每条带 `kind` 和 `display_zh`，界面照写，不自己拼。
