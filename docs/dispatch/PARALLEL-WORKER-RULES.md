# B/C独立并行执行纪律

适用于WATER-W1-B与WATER-W1-C；**不适用A的Rust专属helper/rules**。总控冻结协议、基线、范围和验收，用户人工外贴；实现者只在自己的独立工作树写入。

- 开工按本票执行parallel-check baseline，核对分支/完整SHA/洁净/本票冻结哈希/Node24。权威票和manifest在主检出，只读即可，不merge取票。
- 各票仅改自己的包/原型、回执和证据。禁止写A树、根Cargo/锁、contracts/v1、总控脚本、登记与其他项目。不能重新设计冻结API；问题写受阻回执交总控。
- 不装npm依赖、浏览器、Rust工具或修改全局配置。B仅人工浏览官方文档用于事实核对，校验器和测试不联网/不读本机环境。C仅测试时开127.0.0.1临时静态服务与自己的隔离Chrome，不用用户浏览器profile、不访问真实数据。
- 禁止真实扫描/清理、用户文件选择器、上传、外部模型调用、上游脚本、通用递归删除、git clean/hard reset、全树还原、stash、批量git add、push/merge/rebase或发布。
- 每票单一写入者；不得另启实现子代理。只读辅助需在回执说明，不得读其他执行树的在途实现。
- 仅跑本票固定Node目标，一次一个检查；不watch/coverage/全仓测试。有效行为先红与负控以本票要求为准，编译/文件缺失/超时不能算目标断言失败，不能植入测试专用开关。
- 实现与证据提交后运行带--final的定向门，要求同一干净SHA；随后只允许单独补报告/证据提交。显式git add允许文件，记录真实实现SHA，检查后产品代码变化需重跑。
- 回执写实现、逐条需求、命令/退出码/日志、负控及恢复哈希、平台未验证、来源/假设、实际引擎模型；报告后停止。受阻保存现场、不要求用户放宽文件范围。
- 没有Git身份时用单命令局部身份Water Worker (external)/water-worker@localhost，不改global config。提交第一行用票号。
- 完成/受阻对话和报告第一行统一：`<本票号> 任务已完成，任务报告在 <实际绝对路径>`，受阻改“任务受阻”。完成只等于SUBMITTED，总控另行验收。

helper只检查约定的元数据与返回结果，不是OS沙箱，不能代替守规、源码审阅和总控独立验证。
