## 3. 夹具与真实数据

- 合成夹具只能建在本树 `.local/` 下工单指定的目录里：
  - 每次用随机名新建一个目录；

- **H3 的整机检查**：
  - 由检查器在本树 `.local/w5-h3-native/` 下生成夹具，七个分类全部关闭，只清理夹具；

  - 它会读本机进程列表判断占用，不读任何文件内容。
- H2 的 `--mode real` 是只读真实冒烟，清理不执行，输出不含路径或命令行。
- 原生窗口只有 H3 的 1 个（`native --final`），选择框 0。H4 的浏览器测试只开一个私有 headless Chrome。

## 4. 检查与负控

| 模式 | 作用 |
|---|---|
| `lock` | Rust 票：锁文件已存在，只核对依赖 |
| `check` | 依赖与源码政策、`cargo fmt --check`、`cargo clippy -D warnings`；H4 为语法检查与界面政策 |
| `test` | 跑工单指定的测试（H4 为单元测试），名字与数量必须完全一致 |
| `browser` | H4 的浏览器测试与截图 |
| `real` | H2 只读真实冒烟 |
| `native` | H3 的夹具清理闭环，只作为 final |
| `red-nc1` 等 | 有效负控 |
| `archive` | 把 `.local/checks/<票号>/` 的回执、日志与截图按原字节复制进证据目录并写索引 |

负控做法：
1. 只改生产代码里真正被调用的那一处，不改测试、不加开关；
2. 运行 `--mode red-ncN`，它必须以目标失败信息失败；
3. **立即**用 `git checkout -- <文件>` 恢复原字节，跑一次 `--mode test` 变绿，再做下一条。

检查器会核对源码哈希。用编译错误、超时或改测试造出的红不算数。H4 的负控由检查器跑浏览器测试证明，恢复后仍跑 `--mode test`。

**机器上同时有几张票在编译与测试**，磁盘可能很忙：
- 服务的 50 ms 返回预算若因此超时一次，可以原样重跑一次 `--mode test`，回执里如实写明；
- 私有 Chrome 若在编译时失去响应（之前出现过一次），可以原样重跑一次 `--mode browser`；
- 连续两次失败就停下写受阻回执。

## 5. 收尾

1. 实现与测试全部提交，得到干净的实现提交。
2. 在这个干净提交上依次跑工单列出的 final。final 会核对负控记录；产品字节不变时不要重复跑。
3. 跑 `--mode archive`，写回执（路径见工单），把回执与证据目录逐个文件 `git add` 后单独提交。
   - 后续提交只能含回执与证据；
   - 证据里的 `.log` 若被忽略，用 `git add -f`。
4. 回执第一行与给用户的通知完全一样：`<票号> 任务已完成，任务报告在 <绝对路径>`；受阻则写“任务受阻”。
5. 回执必须写清：
   - 实际模型；
   - 实现提交 SHA；
   - 逐条对照 SPEC；
   - 每个检查命令与结果；
   - 负控：改了哪一处、失败信息、恢复后的哈希；
   - H2 的真实冒烟摘要；H3 的整机步骤、用时、退出码与截图；H4 逐张截图写看到了什么；
   - 没做或没验证的事。

**远端与历史**：
- 不 push 到任何远端，不添加或修改 git 远端与配置；
- 不改写已有提交（不 amend、reset、squash、rebase 或任何强制操作），只在首次 HEAD 之后新增提交；
- 提交信息写错就在回执里说明，不要改写。

禁止：merge、`git add -A`、`git clean`、`git stash`、改主线台账、提交别人的文件。交回后停止一切测试与后台进程。
