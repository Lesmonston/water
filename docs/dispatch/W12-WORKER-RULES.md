- **五张同时开工**，各改各的目录。跨目录的接口（执行器的 `journal_error` 与 `JournalFailed`）总控已写进基线，P1 与 P2 都在它之上做，互不等待。
- 模式与负控做法照通用规则第 6 节；`lock`、`check`、`test`、`browser`、`real`、`native`、`archive` 的含义与第十一波相同。

## 2. 第十二波共同的

- **旧断言**：工单预列了“获准修改”的，照预列迁移；没预列但因本单必然要变的，照通用规则第 3 节第 1 条直接迁移，不得变弱，回执逐条写原值 → 新值 → 为什么。
- **测试个数不变**：新断言加在已有测试函数里。
- **依赖**：不改任何 `Cargo.toml` 的依赖与 `Cargo.lock`，不改 `package.json`。
- **系统函数**：不新增，照各包现有的。
- **计时**：不加新的墙钟时限断言。只因计时失败的照通用规则第 3 节第 2 条处理。
- **隔离根**：测试的隔离根一律在本树 `.local/` 下，不得建在任何盘根。唯一例外是 P3 的整机检查，由检查器驱动（同第十一波 N2）。

## 3. 真实数据（一律只读，输出只有计数或组级汇总）

| 单 | 真实冒烟读什么 |
|---|---|
| P1 | 各固定盘两个名字的隔离根的状态与编号目录个数（同第十一波 N3）；不移入、不复原、不删除 |
| P2 | 一次只读真实体检，清理关闭（同第十一波 N8） |
| P3 | 整机检查只清理本树夹具；数据目录用检查器给的 `WATER_DATA_DIR`，不碰 `%LOCALAPPDATA%` 下的真实 Water 或 Flick 目录 |
| P4 | 不读真实数据（浏览器只用夹具） |
| P5 | 已知目录是否存在（同第十一波 N4） |

## 4. 机器负载

- 同一时间机器上可能有四五张单在编译与测试。跑 cargo 前按进程名看一眼；别的单在跑测试时，计时类断言偶尔会超，照通用规则第 3 节第 2 条重跑。
- 交回后停止一切测试与后台进程（包括无头浏览器）。
