## 3. 夹具与真实数据

- 合成夹具只能建在本树 `.local/` 下：
  - 每次用随机名新建一个目录；
  - 测试结束**只删除本次新建的那一个目录**（校验父目录与名字前缀）；
  - 不得递归删除任何别的东西。
- J3 的 `--mode real` 是服务的只读真实体检：会读本机文件名、大小、时间与进程列表，不读文件内容，不清理，输出不含路径。
- J4 的 `--mode real` 只核对本机已知目录是否存在，不读文件内容，输出不含路径。
- **J1 的整机检查**与第六波 I2 相同：检查器在本树 `.local/w7-j1-native/` 下生成夹具，七个分类全部关闭，只清理夹具；受保护的位置照规则只读统计占用。原生窗口只有这 1 个（`native --final`），选择框 0。
- J2 的浏览器测试只开一个私有 headless Chrome。

## 4. 检查与负控

| 模式 | 作用 |
|---|---|
| `lock` | Rust 票：锁文件已存在，只核对依赖 |
| `check` | 依赖与源码政策、`cargo fmt --check`、`cargo clippy -D warnings`；J2 为语法检查与界面政策 |
| `test` | 跑工单指定的测试（J2 为单元测试），名字与数量必须完全一致 |
| `browser` | J2 的浏览器测试与截图 |
| `real` | J3、J4 的只读真实冒烟 |
| `native` | J1 的夹具清理闭环，只作为 final |
| `red-nc1` 等 | 有效负控 |
| `archive` | 把 `.local/checks/<票号>/` 的回执、日志与截图按原字节复制进证据目录并写索引 |

负控做法：
1. **只改生产代码里真正被调用的那一处**，不改测试、不加开关。检查器只认生产源码目录下的改动：J1 是 `apps/water/host/src/`，J2 是 `apps/water/ui/` 下的产品文件，J3 是 `packages/water-service/src/`，J4 是 `packages/junk-rules/src/`（只改规则数据不算）；
2. 运行 `--mode red-ncN`，它必须以目标标记失败；
3. **立即**用 `git checkout -- <文件>` 恢复原字节，跑一次 `--mode test` 变绿，再做下一条。

检查器会核对源码哈希。用编译错误、超时或改测试造出的红不算数；别的测试先超时、或先撞上旧标记失败，检查器也不认，要换更窄的改动位置。J4 是纯数据票，生产代码里大多数位置已被旧断言覆盖，要找只有新断言才抓得到的位置（第六波 I1 的经验：旧断言会先失败）。

**机器上同时有几张票在编译与测试**，磁盘可能很忙：
- 私有 Chrome 若在编译时失去响应，可以原样重跑一次 `--mode browser`；
- 连续两次失败就停下写受阻回执。

## 5. 收尾

1. 实现与测试全部提交，得到干净的实现提交。
2. 在这个干净提交上依次跑工单列出的 final。final 会核对负控记录；产品字节不变时不要重复跑。
3. 跑 `--mode archive`，写回执（路径见工单），把回执与证据目录逐个文件 `git add` 后单独提交。
   - 后续提交只能含回执与证据（包括归档器生成的 `.gitattributes`）；
   - 证据里的 `.log` 若被忽略，用 `git add -f`。
4. 回执第一行与给用户的通知完全一样：`<票号> 任务已完成，任务报告在 <绝对路径>`；受阻则写“任务受阻”。
5. 回执必须写清：
   - 实际模型；
   - 实现提交 SHA；
   - 逐条对照 SPEC；
   - 每个检查命令与结果；
   - 负控：改了哪一处、失败信息、恢复后的哈希；
   - 改过的旧断言：原值、新值；
   - J1 的整机步骤、用时、退出码与截图；J2 逐张截图写看到了什么；J3、J4 的真实冒烟结果；
   - 没做或没验证的事。

**提交身份**：本机没有配置 git 身份，也不许改配置。只在提交命令的进程里设 `GIT_AUTHOR_NAME`、`GIT_AUTHOR_EMAIL`、`GIT_COMMITTER_NAME`、`GIT_COMMITTER_EMAIL`，用**执行者自己的名字**（如模型名）与 `<名字>@localhost` 这类地址。**不要借用仓库里已有的人类作者身份。**

**远端与历史**：
- 不 push 到任何远端，不添加或修改 git 远端与配置；
- 不改写已有提交（不 amend、reset、squash、rebase 或任何强制操作），只在首次 HEAD 之后新增提交；
- 提交信息写错就在回执里说明，不要改写。

禁止：merge、`git add -A`、`git clean`、`git stash`、改主线台账、提交别人的文件。交回后停止一切测试与后台进程。
