## 1. 原则（每条都能检验）

1. **一屏一件事，一个主按钮。** 主按钮上写后果和体量，例如“清理推荐项 15.4 GB”。
2. **普通情况三次点击清完**：开始体检 → 清理推荐项 → 开始清理。
3. **要你判断的最多 5 张卡。** 每张一句结论、一行证据、两个按钮（清理 / 保留）。超过 5 张时按体量取前 5，其余放进明细。
4. **只统计不清理的、受保护的，默认各收成一行。**
5. **结论由服务算，界面只显示。** 你的每个决定（卡片选清理或保留、某一类不清）都交给服务，服务返回新的计划；界面不自己维护勾选树。
6. **不出现“只影响显示”的筛选。** 看到什么就清什么。
7. **少用的操作收进“⋯”菜单**，不在每一行铺文字链接。
8. **扫哪里在首页选，扫什么在设置里。**
9. **同一页不出现两套勾选。** 复选框只在“明细”和分组抽屉里出现。

## 3. 页面

### 3.1 体检首页：选位置

从上到下：

0. **隔离区条**（隔离区还有东西时才出现，用户 11-02 要求常驻）：一行浅色玻璃“隔离区还有 4.8 GB · 最早的放了 7 天”，右侧次按钮“打开文件夹”（宿主用资源管理器打开）与文字按钮“去隔离区”。Water 清掉、或用户在资源管理器里删掉后，下次核对时消失；只剩删不掉的文件时写“还剩 3 个文件删不掉”。这一条在结论页顶部同样出现。
1. **磁盘行**：每个固定盘一块小玻璃，盘符、可用 GB、细水位条；系统盘多一个小水位瓶。剩余不足 10% 时细条变橙。不再有占半屏的系统盘大卡。
2. **体检卡**（主角）：标题“这次检查哪里？”，下面一行位置胶囊：
   - `C 盘常用位置`：AI 工具、浏览器、临时文件等，类别在设置里改；默认选中；
   - 每个非系统固定盘一枚：`D 盘`、`E 盘`、`F 盘`（整盘）；
   - 已加过的文件夹各一枚（显示最后一级名字，悬停显示完整路径）；
   - `＋ 文件夹`：打开系统选择框（后端打开）。
   - 胶囊点一下选中、再点取消。**新加的文件夹自动单独选中**，其它胶囊取消，这样新位置单独成一次清理，不和常用位置的默认勾选混在一起（启发第 19 条的 F1 场景）。
   - 盘与文件夹胶囊的“⋯”菜单：`查重复文件`（见 3.13）；文件夹另有 `从列表移除`。
3. **主按钮**“开始体检”，旁边一句“只读取文件名、大小与时间”。
4. **提醒**（最多两条，没有就不出现）：上次结果还在时“上次体检 · 10 月 26 日 · 可清 31.2 GB · 查看结果”；已经 7 天没体检；某个泄漏还在长。隔离区不在这里，用第 0 条的常驻条。

### 3.2 体检中

沿用 v1 的水波进度环。右侧只列本次选的位置，每个一行：等待 / 扫描中 / 完成（体量）。次按钮“停止”。

### 3.3 结论页（核心）

页头一行：“这次看了：C 盘常用位置、F 盘 · 10 分钟前 · 用时 48 秒”，右侧文字按钮“重新体检”（回到 3.1）。

1. **主结论**（不加卡片）：
   - 眉题“可以放心清理”，超细大号“15.4 GB”；
   - 一行构成：“缓存 12.1 GB · 旧版本 3.3 GB · 比上次多 2.1 GB · Chrome 开着，会跳过约 0.4 GB”；
   - 主按钮“清理推荐项 15.4 GB”，旁边文字按钮“包含什么”：就地展开最多 8 行类别汇总（类别、体量、组数，比上次新出现或变大的标“新”），每行右侧一个开关“清 / 不清”，关掉就是这一类这次不清。开关交给服务，服务重算计划。
2. **需要你看一眼**（0～5 张卡，两列）：
   - 卡片：级别圆点 + 一句结论（如“`fix-r9\.tmp_w35b` 里有 81 个同模板目录，还在长”）、一行证据（数量、最早与最新时间、所在位置）、右上体量；
   - 两个按钮：次按钮“保留”、主色描边按钮“清理”；右上“⋯”菜单：`以后都跳过`、`查看明细`；
   - 选了以后卡片收成一行“已加入清理 · 2.1 GB · 撤销”或“已保留 · 撤销”，主结论的按钮体量随之更新（如“清理 19.0 GB”）；
   - 泄漏类卡片多一行橙色小字“清了不修，会再长回来”，菜单多一项 `复制线索给 agent`；
   - 会话卡片（用户在设置里打开了这个工具的开关才出现）多一行“清掉后这些对话不能再续接或回看；可以先放进隔离区试试”；
   - 卡片按体量排，只出最大的 5 张；其余在卡片下方合成一行（见 3.12 第 4 条）。
3. **交给 agent**（有才出现）：一行一条，左边一句话（如“`F:\new\denglou\.worktrees` 里 11 棵树已脱离 git，要先查有没有未提交的改动”），右边按钮“复制线索”。复制的是给项目 agent 的检查清单（第十波计划第 3 节）。超过 3 条时只显示 3 条，其余收进“还有 N 条 ›”。
4. **收起的几行**（每行一句话，点开就地展开为只读清单）：
   - “还有 6.3 GB 只统计、不清理：Git 工作树、程序自带的依赖、浏览器数据 ›”
   - “9.7 GB 受保护：会话记录、登录数据 ›”
   - “空间分布：F 盘最大的是 denglou 319 GB、Steam 194 GB… ›”（这次体检了整盘才出现）
   - “4 条系统建议，可以再腾出约 33 GB，要在 Windows 设置里改 ›”（页面文件、组件存储、传递优化、Chrome 端侧模型、回收站；Water 不替你改）
5. 页脚文字按钮“查看全部明细”（进 3.5）。

页面上没有底部操作坞，没有筛选条，没有复选框。

### 3.4 分组抽屉

从卡片、明细或收起清单里的一行打开。右侧抽屉，宽 480px：
- 头部：级别圆点 + 标题、体量、一句“这是什么”；
- 两行要点：“清了会怎样”“为什么这样判断”（v1 的三段说明合并成两行）；
- 条目清单**默认是汇总行，不是逐个文件**（3.12 第 3 条）：按位置或模板合并，例如“`jest_*` × 33 · 3.6 GB”“`chrome_*` × 9 · 0.6 GB”“其它 8,428 个文件 · 1.2 GB”，最多 8 行；每行左边一个复选框（取消即这次不清这一行），右边“⋯”菜单：`以后都跳过`、`展开看每一项`；在用的灰显并写“Chrome 正在使用，关掉后可清”；
- 组里只有几项（不超过 8 项）时直接逐项列出；
- 想找某一项时用抽屉顶部的搜索框，搜出来的才逐项显示；
- 底部一行：“这一组这次清 3 项 · 2.1 GB”。

### 3.5 明细

给想细看的人，但不再一次铺开几十组：
- 顶部一个分段控件 `按类别 | 按位置`，和一个搜索框；
- **默认只有类别行**（最多 9 行）：类别名、组数、体量、本次清多少；点一行就地展开这一类的组，同时只展开一类；
- 每组一行：复选框（只有可清的组有）、标题、位置标签、级别圆点、体量、箭头（开抽屉）。**同一规则在几个位置的组合成一行**，位置标签写“3 个位置”，点开抽屉再按位置分；
- 和上次一样、没变化的组折叠成一行“和上次一样的 23 组 · 12.8 GB ›”；
- 受保护与仅供参考放在最后一类，没有复选框；
- 底部一行汇总与主按钮“清理所选 X GB”，与结论页同一份计划（在明细里改了，结论页的数字同步变）。

### 3.6 确认清理

居中浮层，标题“清理 19.0 GB？”，下面两块（第十波计划 4.5：推荐的缓存直接删，需确认的先隔离）：
- **直接删除 15.4 GB**：缓存与旧版本，会自动重新生成。按类别列出体量；
- **你选的 3.6 GB**：列出卡片里你选的那几项，上方一个二选一（用户 11-02 要求，会话记录尤其需要）：
  - `先放进隔离区`（默认）：还在原来的盘上，可以还原；会话可以先试着继续对话，没问题再到隔离区删除；
  - `直接删除`：马上腾出空间，不能恢复。选了这一项，主按钮变成红色“删除 19.0 GB”；
- 一行预计跳过：“Chrome 开着，约 0.4 GB 会跳过；关掉 Chrome 再清可以多腾出这些”；
- 按钮：次按钮“取消”、主按钮“开始清理”。直接删除的部分是可再生的缓存，主按钮用强调蓝；红色只留给不可恢复的删除：隔离区里的“永久删除”，以及上面选了“直接删除”时。

### 3.7 清理中、完成

清理中沿用 v1。完成页：
- 超细大号“已腾出 15.0 GB”，下一行“另有 3.6 GB 在隔离区，确认没问题后再永久删除”；
- 每个涉及的盘一个小水位瓶，清理前后的可用空间；
- 有部分完成或失败时，一行说明 + “查看”；
- 按钮：主按钮“完成”（回到结论页，已清的不再出现）、文字按钮“去隔离区”。

### 3.8 隔离区

- 页头：“隔离区占用 4.8 GB。放在原来的盘上，确认没问题后再永久删除。”右侧次按钮“打开文件夹”。
- 每次清理一张卡：日期、体量、几项、放了几天；条目按汇总行显示（同 3.4）。按钮：次按钮“还原”、红色文字按钮“永久删除”（二次确认）；“⋯”菜单：`打开文件夹`、`查看全部条目`。
- 放满 7 天的卡片顶部一行提醒，不自动删。
- **删了还剩**：永久删除后有删不掉的，卡片变成“还剩 3 个文件删不掉 · 12 MB”，逐个写原因，例如“WorkBuddy 正在用（关掉后再试）”“名字是系统保留名 `nul`（Water 能删，点再试一次）”“没有权限”；按钮“再试一次”“打开文件夹”。只要还剩，首页的隔离区条就一直在。
- 用户在资源管理器里自己删掉了，下次核对时卡片消失；只删了一部分，卡片按剩下的体量更新。

### 3.9 趋势

三块，从上到下：
1. **几天后满**：每个盘一块小玻璃，“约 23 天后满”或“十年内不会满”或“需要 3 天内 3 次体检”。
2. **一直在长的**：泄漏簇与增长最快的组，每行：名称、增速、状态（仍在长 / 已止住 / 疑似）；“⋯”菜单：`标记为已修`、`复制线索给 agent`。
3. **残留进程**：默认收起一行“3 个残留进程，占 1.3 GB 内存 ›”，只列不结束。

可用空间曲线放在“几天后满”的盘块里点开看，不单独占一块。

### 3.10 记录

时间倒序：体检与清理。每行一句话 + 体量；停下的体检写“已停止”。点开看详情。不变。

### 3.11 设置

左侧小导航四项：
- **扫描内容**：“常用位置”里查哪些类别（v1 的 7 个开关），受保护类说明只统计；下面一节“会话记录”：每个 agent 工具一行，写着它自己的保留规则（如“Claude Code 默认删 30 天前的会话”）、当前体量、最大的一个会话，右侧开关“允许清理 30 天前的会话”（天数可选 7 / 30 / 90），默认关；
- **跳过名单**：“以后都跳过”的项，每行一个“移除”；
- **项目声明**：发现的 `.water-cleanup.json`，信任 / 不信任，显示它声明了什么（第十波计划 4.4）；
- **关于与隐私**：v1 5.11 的内容。

### 3.12 长列表（用户 11-02：“每次扫描之后列表都太多了，用户逐项要去看几百条”）

一次真实体检有 39 组、6,750 项；`system-temp-old` 一组就有 8,470 项。规则：

1. **人最多看三层**：一个结论数字 → 最多 5 张判断卡 → 每组最多 8 行汇总。条目级只在搜索、或在“⋯”里点 `展开看每一项` 时出现。
2. **同一规则在几个位置合成一行**：例如“Rust 构建产物 · 3 个位置 · 15.8 GB”，不再出现连着三行同名的组。
3. **同模板的条目合成一行**：按名字模板（随机尾巴换成 `*`）或子目录合并，写数量、体量、最早与最新时间，例如“`verify-******` × 81 · 2.1 GB”；剩下的合成“其它 N 项”。一行汇总可以整行勾掉，也可以 `以后都跳过`。
4. **小的不出卡**：待判断的项按体量排，最大的 5 张出卡；其余合成一行“还有 7 项需要判断，都小于 100 MB，共 240 MB，默认不清 ›”，点开进明细里的“需要确认”一类。
5. **记住你的决定**：卡片选过“保留”的，同一项下次只要没变大就不再出卡，汇总进“你上次保留的 3 项 ›”；选过 `以后都跳过` 的不再出现。
6. **只突出变化**：和上次体检相比没变化的组，在明细里折叠成“和上次一样的 23 组”；新出现或变大的标“新”。
7. **收起的东西只说一句话**：仅供参考、受保护、空间分布、系统建议、交给 agent 的多余条目，都各收成一行，写清体量与前两三个名字。
8. **汇总由服务算**：结论视图直接给出卡片、汇总行与“其它 N 项”，界面不自己合并、不自己排序。

验收（对应第十波计划 4.7）：真实体检里，结论页的行数（不含展开）不超过 20 行；任何一个抽屉默认不超过 8 行汇总；用户本人说“这次少看了”才算过。

### 3.13 查重复文件

用户 11-02 同意做（ADR-019 第 7 节）。入口只在首页盘与文件夹胶囊的“⋯”菜单：`查重复文件`。

1. **先说明再开始**：浮层写“查重要读文件内容来比对，只在这台电脑上算，不保存内容、不上传。只比大小相同的文件，可能要几分钟。”按钮“开始查重”。
2. **进行中**：和体检中同一种进度环，写已比对的文件数与发现的重复体量；可以停止。
3. **结果**：一个数字“多出来 9.0 GB”，下面每组一行：文件名、份数、每份大小、建议留哪份（写理由：“这份在‘以这里为准’的文件夹里”“这份更早”）；默认都不勾。勾上的组清理时先进隔离区。
4. 名字相同但内容不同的不算重复，在结果底部写一句“另有 3 组同名不同内容，没有列入”。
5. 组太多时同样按 3.12：最大的 8 组逐行列出，其余合成一行。

## 5. 交互规则

1. **默认值**：主结论只含“推荐”级别；判断卡默认都未决定，未决定的不清。
2. **决定可撤销**：卡片的决定、“包含什么”的开关、明细里的勾选，在点“开始清理”前都能撤销；同一份计划，三处同步。
3. **重新体检后**：已经决定“保留”的卡片，同一项下次还出现时默认仍是“保留”，并写“上次你选了保留”；要永久不再出现用“以后都跳过”。
4. **新位置单独清**：首页新加的文件夹自动单独选中；结论页页头写明“这次只看了这个文件夹”。
5. **在用**：在用的项照常列出，灰显并写解除条件（关掉什么、改哪条联接）；确认框写预计跳过的量。
6. **结果过期**（有新体检、清理过或跳过名单变了）：页头一行“结果已过期 · 重新体检”，主按钮停用。
7. **进行中**：体检或清理进行中，导航可切换，体检页显示进度；关闭窗口时若正在清理，先问。
8. **空状态**：没有可清的时，主结论写“没有可以放心清理的东西”，不显示主按钮；没有判断卡就不出现这一节。

## 6. 服务要给什么（“结论视图”，契约草案的要点）

界面只发 ID 和决定，不发路径，不自己算选择状态。冻结契约时细化。

- `conclusion_get`：本次范围（位置列表、时间、用时）；主计划（体量、按类别、按盘、预计跳过及原因）；判断卡（最多 5 张：ID、类型、结论句、证据、体量、级别、当前决定、可用的菜单项）；交给 agent 的线索（ID、一句话、可复制的文本）；仅供参考汇总、受保护汇总（体量与前三个名称）；明细里还剩多少项需要判断。
- `conclusion_decide`：卡片 ID + `clean | keep | undecided`，或类别 ID + `include | exclude`，或条目 ID 的排除；返回新的 `conclusion`。
- 明细、抽屉沿用 `scan_result`、`group_detail`，勾选也走 `conclusion_decide`。
- `clean_prepare` 只接收结论视图的版本号，服务按它出计划，确认框显示计划里的两块（直接删除、移到隔离区）与预计跳过。
- 结论视图与抽屉都直接给汇总行（3.12）：同规则多位置合并、同模板条目合并、“其它 N 项”、“还有 N 项需要判断”、“你上次保留的”、“和上次一样的”；界面不合并、不排序。
- 确认：`clean_prepare` 带上“你选的部分”是先隔离还是直接删除。
- 隔离区：`quarantine_list`（含每个隔离目录还在不在、剩多少、删不掉的项及原因）、`quarantine_restore`、`quarantine_delete`、`quarantine_reveal`（用资源管理器打开，只收隔离编号）（第十波计划 M4、M5、M7）。
- 查重：`dedupe_start`（位置 ID）、`dedupe_progress`、`dedupe_cancel`、`dedupe_result`、按组决定（第十波计划 M8）。
- 会话开关：`locations_set_session_cleanup`（工具 ID、开关、天数）。
- 位置：首页用 `locations_get` 的盘与文件夹；`scan_start` 带本次选中的位置 ID。

## 7. 验收（界面部分，对应第十波计划 4.7）

- 在真实结果上，清一次推荐项不超过 3 次点击；判断卡不超过 5 张；
- 页面上没有“只影响显示”的筛选，同一页只有一套勾选；
- 设计稿与实现的截图逐页对照；
- 最后由用户本人用一次，说“这次少看了”才算过。

## 8. 不变的

- 只读取文件名、大小与时间；界面从不发送或拼接路径，“添加文件夹”由后端打开选择框；
- 受保护类永远不可清；
- 材质、颜色、字体、动效、品牌（v1 第 2、10 节）。
