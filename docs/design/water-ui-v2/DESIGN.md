## 0. 为什么重做

用户 11-02 的两条意见（[清理记录](../../maintenance/CLEANUP-20261101.md)启发第 18、19 条）：
- 选位置：“你现在选择扫描位置不能指定某个具体的盘，而且指定扫描位置的按钮应该放在主页。目前的扫描位置页大部分内容是扫描的项点，而非位置。”
- 结果页：“现在这个排版页非常不合理，下拉菜单太长了。选项太多了，一般人没办法去这样逐条去看，如果是这样设计，那还不如让aget去扫描了，没有减少人的工作量。”

总控按第六次整合的 31 张界面截图逐页走了一遍，问题如下：

| 页面 | 问题 |
|---|---|
| 首页 | 只有一个“开始体检”，扫哪里要去另一页设；系统盘大卡、开始卡、上次体检卡、泄漏横幅四块各说一件事，没有主次 |
| 扫描位置 | 名字是“位置”，内容是 7 个类别开关；自定义文件夹在页面最底下；选不了某个盘 |
| 结果页 | 一页铺开全部类别和组（实测 39 组、6,750 项）；三层勾选：类别全选、组复选框、抽屉里的条目复选框；三套筛选叠在一起：按盘、按级别、按体量或增长，还要一句“筛选只影响显示，清理包含全部已选分组”来提醒；受保护、仅供参考的组夹在可清的中间，每行一个锁；同名组看不出各属于哪个位置（“测试浏览器配置”连着三行） |
| 底部操作坞 | “已选 39 组 · 6,750 项 · 93.7 GB”无法核对，用户要靠总控读计划才知道勾了什么 |
| 分组抽屉 | 先是三段说明文字，再是条目；每一项下面都有一条“以后都跳过”文字链接 |
| 确认框 | 只能看组名和体量，看不出哪些会因为在用被跳过、能腾出多少 |
| 导航 | 五项里“扫描位置”名不副实；“增长趋势”里混着几天后满、残留进程、可用空间曲线 |

根子是：界面把整份扫描结果原样摊给人，让人自己挑。第八波 K6 补了五次单，问题都出在界面自己算勾选状态。

## 1. 原则（每条都能检验）

1. **一屏一件事，一个主按钮。** 主按钮上写后果和体量，例如“清理推荐项 15.4 GB”。
2. **普通情况三次点击清完**：开始体检 → 清理推荐项 → 开始清理。
3. **要你判断的最多 5 张卡。** 每张一句结论、一行证据、两个按钮（清理 / 保留）。超过 5 张时按体量取前 5，其余放进明细。
4. **只统计不清理的、受保护的，默认各收成一行。**
5. **结论由服务算，界面只显示。** 你的每个决定（卡片选清理或保留、某一类不清）都交给服务，服务返回新的计划；界面不自己维护勾选树。
6. **不出现“只影响显示”的筛选。** 看到什么就清什么。
7. **少用的操作收进“⋯”菜单**，不在每一行铺文字链接。
8. **扫哪里在首页选，扫什么在设置里。**
9. **同一页不出现两套勾选。** 复选框只在“明细”和分组抽屉里出现。

## 3. 页面

### 3.1 体检首页：选位置

从上到下：

1. **磁盘行**：每个固定盘一块小玻璃，盘符、可用 GB、细水位条；系统盘多一个小水位瓶。剩余不足 10% 时细条变橙。不再有占半屏的系统盘大卡。
2. **体检卡**（主角）：标题“这次检查哪里？”，下面一行位置胶囊：
   - `C 盘常用位置`：AI 工具、浏览器、临时文件等，类别在设置里改；默认选中；
   - 每个非系统固定盘一枚：`D 盘`、`E 盘`、`F 盘`（整盘）；
   - 已加过的文件夹各一枚（显示最后一级名字，悬停显示完整路径）；
   - `＋ 文件夹`：打开系统选择框（后端打开）。
   - 胶囊点一下选中、再点取消。**新加的文件夹自动单独选中**，其它胶囊取消，这样新位置单独成一次清理，不和常用位置的默认勾选混在一起（启发第 19 条的 F1 场景）。
   - 文件夹胶囊的“⋯”菜单：`从列表移除`。
3. **主按钮**“开始体检”，旁边一句“只读取文件名、大小与时间”。
4. **提醒**（最多两条，没有就不出现）：上次结果还在时“上次体检 · 10 月 26 日 · 可清 31.2 GB · 查看结果”；隔离区有放满 7 天的；已经 7 天没体检；某个泄漏还在长。

### 3.2 体检中

沿用 v1 的水波进度环。右侧只列本次选的位置，每个一行：等待 / 扫描中 / 完成（体量）。次按钮“停止”。

### 3.3 结论页（核心）

页头一行：“这次看了：C 盘常用位置、F 盘 · 10 分钟前 · 用时 48 秒”，右侧文字按钮“重新体检”（回到 3.1）。

1. **主结论**（不加卡片）：
   - 眉题“可以放心清理”，超细大号“15.4 GB”；
   - 一行构成：“缓存 12.1 GB · 旧版本 3.3 GB · Chrome 开着，会跳过约 0.4 GB”；
   - 主按钮“清理推荐项 15.4 GB”，旁边文字按钮“包含什么”：就地展开最多 8 行类别汇总（类别、体量、组数），每行右侧一个开关“清 / 不清”，关掉就是这一类这次不清。开关交给服务，服务重算计划。
2. **需要你看一眼**（0～5 张卡，两列）：
   - 卡片：级别圆点 + 一句结论（如“`fix-r9\.tmp_w35b` 里有 81 个同模板目录，还在长”）、一行证据（数量、最早与最新时间、所在位置）、右上体量；
   - 两个按钮：次按钮“保留”、主色描边按钮“清理”；右上“⋯”菜单：`以后都跳过`、`查看明细`；
   - 选了以后卡片收成一行“已加入清理 · 2.1 GB · 撤销”或“已保留 · 撤销”，主结论的按钮体量随之更新（如“清理 19.0 GB”）；
   - 泄漏类卡片多一行橙色小字“清了不修，会再长回来”，菜单多一项 `复制线索给 agent`。
3. **交给 agent**（有才出现）：一行一条，左边一句话（如“`F:\new\denglou\.worktrees` 里 11 棵树已脱离 git，要先查有没有未提交的改动”），右边按钮“复制线索”。复制的是给项目 agent 的检查清单（第十波计划第 3 节）。
4. **收起的两行**：
   - “还有 6.3 GB 只统计、不清理：Git 工作树、程序自带的依赖、浏览器数据 ›”
   - “9.7 GB 受保护：会话记录、登录数据 ›”
   - 点开就地展开为只读清单。
5. 页脚文字按钮“查看全部明细”（进 3.5）。

页面上没有底部操作坞，没有筛选条，没有复选框。

### 3.4 分组抽屉

从卡片、明细或收起清单里的一行打开。右侧抽屉，宽 480px：
- 头部：级别圆点 + 标题、体量、一句“这是什么”；
- 两行要点：“清了会怎样”“为什么这样判断”（v1 的三段说明合并成两行）；
- 条目清单：路径（中间省略）、体量、最近活动；可清的组每行左边一个复选框（取消即这次不清这一项），每行右边一个“⋯”菜单：`以后都跳过`；在用的项灰显并写“Chrome 正在使用，关掉后可清”；
- 底部一行：“这一组这次清 3 项 · 2.1 GB”。

### 3.5 明细

给想细看的人，就是 v1 结果页的内容，但只保留一套控件：
- 顶部一个分段控件 `按类别 | 按位置`，和一个搜索框；
- 每组一行：复选框（只有可清的组有）、标题、所在位置标签（同名组靠它区分）、级别圆点、体量、箭头（开抽屉）；
- 受保护与仅供参考的组排在最后，各自一节，没有复选框；
- 底部一行汇总与主按钮“清理所选 X GB”，与结论页同一份计划（在明细里改了，结论页的数字同步变）。

### 3.6 确认清理

居中浮层，标题“清理 19.0 GB？”，下面两块（第十波计划 4.5：推荐的缓存直接删，需确认的先隔离）：
- **直接删除 15.4 GB**：缓存与旧版本，会自动重新生成。按类别列出体量；
- **移到隔离区 3.6 GB**：7 天内可在“隔离区”还原。列出卡片里你选的那几项；
- 一行预计跳过：“Chrome 开着，约 0.4 GB 会跳过；关掉 Chrome 再清可以多腾出这些”；
- 按钮：次按钮“取消”、主按钮“开始清理”。直接删除的部分是可再生的缓存，主按钮用强调蓝；红色只留给隔离区里的“永久删除”。

### 3.7 清理中、完成

清理中沿用 v1。完成页：
- 超细大号“已腾出 15.0 GB”，下一行“另有 3.6 GB 在隔离区，确认没问题后再永久删除”；
- 每个涉及的盘一个小水位瓶，清理前后的可用空间；
- 有部分完成或失败时，一行说明 + “查看”；
- 按钮：主按钮“完成”（回到结论页，已清的不再出现）、文字按钮“去隔离区”。

### 3.8 隔离区

- 页头：“隔离区占用 4.8 GB。放在原来的盘上，确认没问题后再永久删除。”
- 每次清理一张卡：日期、体量、几项、放了几天；展开看条目。按钮：次按钮“还原”、红色文字按钮“永久删除”（二次确认）。
- 放满 7 天的卡片顶部一行提醒，不自动删。

### 3.9 趋势

三块，从上到下：
1. **几天后满**：每个盘一块小玻璃，“约 23 天后满”或“十年内不会满”或“需要 3 天内 3 次体检”。
2. **一直在长的**：泄漏簇与增长最快的组，每行：名称、增速、状态（仍在长 / 已止住 / 疑似）；“⋯”菜单：`标记为已修`、`复制线索给 agent`。
3. **残留进程**：默认收起一行“3 个残留进程，占 1.3 GB 内存 ›”，只列不结束。

可用空间曲线放在“几天后满”的盘块里点开看，不单独占一块。

### 3.10 记录

时间倒序：体检与清理。每行一句话 + 体量；停下的体检写“已停止”。点开看详情。不变。

### 3.11 设置

左侧小导航四项：
- **扫描内容**：“常用位置”里查哪些类别（v1 的 7 个开关），受保护类说明只统计；
- **跳过名单**：“以后都跳过”的项，每行一个“移除”；
- **项目声明**：发现的 `.water-cleanup.json`，信任 / 不信任，显示它声明了什么（第十波计划 4.4）；
- **关于与隐私**：v1 5.11 的内容。

## 4. 按钮与菜单

| 类型 | 样子 | 用在哪 | 规则 |
|---|---|---|---|
| 主按钮 | 强调蓝实心胶囊，高 40px | 每屏最多一个：开始体检、清理推荐项、开始清理、完成 | 文案写后果，涉及空间的带体量 |
| 次按钮 | 白色玻璃胶囊 | 取消、保留、还原、重新体检 | |
| 卡片主选 | 强调蓝细描边胶囊，高 32px | 判断卡上的“清理” | 与“保留”成对出现，宽度相同 |
| 文字按钮 | 强调蓝文字 | 包含什么、查看全部明细、查看结果 | 不放在列表的每一行里 |
| 危险按钮 | 红色文字按钮，确认框里红色实心 | 只有隔离区的永久删除 | |
| 位置胶囊 | 玻璃胶囊，选中为强调蓝浅底 + 蓝字 + 勾 | 首页选位置 | 点一下切换；文件夹胶囊带“⋯” |
| “⋯”菜单 | 24px 圆形按钮，点开是一块浮层玻璃，最多 4 项 | 卡片、抽屉条目、文件夹胶囊、趋势行 | 只放少用的操作；危险项排最后、红字 |
| 开关 | v1 开关 | 结论页“包含什么”、设置的扫描内容 | |
| 复选框 | v1 复选框 | 只在明细与分组抽屉 | |
| 分段控件 | v1 分段控件 | 明细的“按类别 / 按位置”、设置左侧导航 | 一页最多一个 |

菜单统一写法：动词开头，最多 6 个字（`以后都跳过`、`查看明细`、`复制线索给 agent` 例外，因为“agent”是固定说法）。

键盘：Tab 顺序与视觉一致；卡片上 `Enter` 为清理、`Delete` 为保留（有焦点提示）；`Esc` 关闭菜单、抽屉、浮层；“⋯”菜单用方向键选择。

## 5. 交互规则

1. **默认值**：主结论只含“推荐”级别；判断卡默认都未决定，未决定的不清。
2. **决定可撤销**：卡片的决定、“包含什么”的开关、明细里的勾选，在点“开始清理”前都能撤销；同一份计划，三处同步。
3. **重新体检后**：已经决定“保留”的卡片，同一项下次还出现时默认仍是“保留”，并写“上次你选了保留”；要永久不再出现用“以后都跳过”。
4. **新位置单独清**：首页新加的文件夹自动单独选中；结论页页头写明“这次只看了这个文件夹”。
5. **在用**：在用的项照常列出，灰显并写解除条件（关掉什么、改哪条联接）；确认框写预计跳过的量。
6. **结果过期**（有新体检、清理过或跳过名单变了）：页头一行“结果已过期 · 重新体检”，主按钮停用。
7. **进行中**：体检或清理进行中，导航可切换，体检页显示进度；关闭窗口时若正在清理，先问。
8. **空状态**：没有可清的时，主结论写“没有可以放心清理的东西”，不显示主按钮；没有判断卡就不出现这一节。

## 6. 服务要给什么（“结论视图”，契约草案的要点）

界面只发 ID 和决定，不发路径，不自己算选择状态。冻结契约时细化。

- `conclusion_get`：本次范围（位置列表、时间、用时）；主计划（体量、按类别、按盘、预计跳过及原因）；判断卡（最多 5 张：ID、类型、结论句、证据、体量、级别、当前决定、可用的菜单项）；交给 agent 的线索（ID、一句话、可复制的文本）；仅供参考汇总、受保护汇总（体量与前三个名称）；明细里还剩多少项需要判断。
- `conclusion_decide`：卡片 ID + `clean | keep | undecided`，或类别 ID + `include | exclude`，或条目 ID 的排除；返回新的 `conclusion`。
- 明细、抽屉沿用 `scan_result`、`group_detail`，勾选也走 `conclusion_decide`。
- `clean_prepare` 只接收结论视图的版本号，服务按它出计划，确认框显示计划里的两块（直接删除、移到隔离区）与预计跳过。
- 隔离区：`quarantine_list`、`quarantine_restore`、`quarantine_delete`（第十波计划 W10-M4、M5、M7）。
- 位置：首页用 `locations_get` 的盘与文件夹；`scan_start` 带本次选中的位置 ID。

## 7. 验收（界面部分，对应第十波计划 4.7）

- 在真实结果上，清一次推荐项不超过 3 次点击；判断卡不超过 5 张；
- 页面上没有“只影响显示”的筛选，同一页只有一套勾选；
- 设计稿与实现的截图逐页对照；
- 最后由用户本人用一次，说“这次少看了”才算过。

## 8. 不变的

- 只读取文件名、大小与时间；界面从不发送或拼接路径，“添加文件夹”由后端打开选择框；
- 受保护类永远不可清；
- 材质、颜色、字体、动效、品牌（v1 第 2、10 节）。
