## 4. 为什么慢、怎么提速

### 4.1 原因

拿第十一波看：8 张单，15:45 出单，20:20 收口，约 4.5 小时。
- **服务单要等执行器合入才能开工**，第二批多等了约 2 小时。
- **每张单总控都新建一棵验收树全部重跑**，还另做变异。轻门的单也重跑一遍，一张二三十分钟。
- **一波只有一个主题**，单子都很小。第十一波主要是改名，计划里的第十二波主要是跳过，用户看得到的变化少。
- **我出单时也有疏漏**：第十一波 N3 的前提、刚才第十二波草稿里三条早已修好的执行器问题。返工也花时间。

### 4.2 做法

1. **每波一批出完，不再分两批**：跨目录的新接口（类型、命令名）由总控先写进基线，各单同时开工。
2. **每波 6～10 张单**：功能和收尾一起排，不再一波一个主题。
3. **验收再减**：
   - 轻门只做审计、看执行者的回执与截图，不重建验收树；
   - 变异只给执行器和服务，各 3 条；
   - 整合时统一重跑全部测试，兜底。
4. **文件少写**：
   - 契约每波一份；
   - 计划直接写到单子能用，不另写派前回执；
   - 出单前先对照已合入的单，避免列已修好的问题。
5. **整合一次跑完**：整合、release、冒烟、复验已经有现成脚本，接成一条命令，约半小时。
6. **执行者多开**：除了 astra、sol，小单可以给 grok 或别的执行者。同时开几个由你定。

按这个做，第十二波 8 张左右的目标是一批出完、半天内收口。

## 5. 要你定的

1. **整体按第 3 节三波走**，第十二波照扩大后的范围（A + B + C）。
2. **提速做法照第 4.2 节**，特别是轻门不再重建验收树。
3. **同时开几个执行者**。
4. **跳过记什么**：推荐“这个位置上的这一类”，新长出来的也跳过。
5. 付费功能、价格与收款（第十三、十四波）可以晚点定。
