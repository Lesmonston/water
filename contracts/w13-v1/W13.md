## 0. 四张单共同的：公开前的写法

开源发布时，这些包会照原样导出到公开仓库（导出脚本 `scripts/release/export-public.mjs` 只复制、不改写，导出后扫描）。本波各单改到或新写的内容（代码、注释、测试、测试数据、样例、README）都照下面写：

- **不写的**：
  - 本机用户名；
  - 本机路径（`F:\new\…` 这类工作目录、`C:\Users\<真实用户名>\…`）；
  - 本机其它项目名；
  - 私人邮箱。
- **测试与样例要用路径时，用虚构的**：
  - 用户目录写 `C:\Users\alice\…`；
  - 工作目录写 `D:\code\<项目名>\…`，项目名用 `demo-app`、`server-kit` 这类通用名字。
- **不写私有流程的引用**：验收、派单、交接的文档路径，工单号，“总控”。代码注释与 README 只写做什么、为什么。
- **范围**：本波只清理各单自己目录里的；别的目录由总控收拾。

## 1. 联接引用（J1，`packages/junk-scan`）

本节替换 [SCAN-M35](../m35-v1/SCAN-M35.md) 第 7.1 节里“哪些联接进索引”和“`referenced_count` 怎么算”的规定，其余照旧。

### 1.1 Windows 自带的兼容联接不进索引

- 遍历中枚举到的重解析点（搜索或测量都算），属性**同时**带 `FILE_ATTRIBUTE_HIDDEN`（0x2）与 `FILE_ATTRIBUTE_SYSTEM`（0x4）的，不进 `junctions`：
  - 不读它的目标；
  - 不算进 10 000 个的上限；
  - 也不参与别的联接 `final_target` 的解析。
- 只带其中一个属性的，照原规则进索引。
- 体检的起点本身是这种联接时，同样处理。
- 属性取自枚举时已经读到的数据，不为此另开文件、不另读属性。
- 其余不变：不跟进去，照原规则记 `reparse_skipped`；标签不是挂载点或符号链接的，照旧不读。

说明：Windows 自带的兼容联接都同时带这两个属性，例如：
- 盘根的 `Documents and Settings`；
- 每个用户目录里的 `Application Data`、`Local Settings`、`My Documents`、`NetHood`、`Recent`、`SendTo`、`Start Menu`、`Templates`；
- `AppData\Local` 里的 `Application Data`、`History`、`Temporary Internet Files`；
- `C:\Users\All Users`、`Default User`。

### 1.2 什么算“被引用”

- `Item.referenced_count` 与 `referenced_by`：索引里 `final_target` **等于条目路径，或位于条目之内**的联接。
- 联接的最终目标**包住条目**（是条目的上级目录）的，**不再算**。
- 联接本身位于条目之内的，照旧不算。
- 比较照旧按段、ASCII 不分大小写。
- `referenced_by` 照旧最多 8 个、升序。`final_target` 的解法照旧（最多 8 次，成环为 None）。

### 1.3 测试（`tests/scan_v1.rs`，标记 `SCAN_W13_JUNCTIONS`）

- **哪些算引用**：夹具里建三种联接：
  - 指向条目本身的，记；
  - 指向条目里面一个子目录的，记；
  - 指向条目所在上级目录的，不记，条目的 `referenced_count` 为 0。
- **属性**：
  - 指向条目本身、并设成隐藏 + 系统的联接，不在 `junctions` 里，条目不记；
  - 指向同一条目、只设隐藏或只设系统的，照记；
  - 设成隐藏 + 系统的联接，照旧记进“联接跳过”。
- **解析**：一个普通联接的目标经过一个隐藏 + 系统联接，不按后者解析；断言 `final_target` 的确切值。
- **迁移**：原 `SCAN_M35_JUNCTIONS` 里“包住条目”那条断言改为不记，逐条写原值 → 新值 → 为什么。其余旧断言不改弱。
- **真实冒烟**（只读）：
  - 在现有真实冒烟上打开联接索引；
  - 报告索引里的联接个数；
  - 逐个只读查索引里每个联接的属性，带隐藏 + 系统的个数必须为 0；
  - 只报计数，不写路径。

## 2. 服务（S1，`packages/water-service`）

### 2.1 跳过之后结论不过期（用户 11-08 定）

- `skip_add`、`skip_unit_add`、`skip_remove` 写入设置后：
  - 最新一次体检的结论**不标过期**；
  - 结论版本照旧加一；
  - 跳过的立刻生效、移除的立刻恢复，都照现有做法；
  - 此前准备的计划照旧作废：用它 `clean_start` 返回 `stale`，过期原因“跳过名单变了”。
- 改的是跳过名单变化时调用的那一处：现在调 `m35::invalidate`，它把整次体检标为过期；改为只作废计划、版本加一。
- 别的设置变化（会话开关、项目声明的信任、类别开关、加减文件夹）照旧标过期。

### 2.2 整组被跳过的泄漏簇不出卡片、不出线索

- 补 [W12](../w12-v1/W12.md) 第 1.3 节最后一条。
- 一个泄漏簇的**每个成员都符合某条跳过记录**时，这个簇不出卡片、不出线索，趋势页也不列它。这里按记录本身判断，不论成员原本可不可清：太新的、按规则保留最新的也算。
- 只有部分成员符合时，照原样出。

### 2.3 日志与隔离的收尾

- **后面的隔离批次整次报日志错误，也当作日志中断**。
  - 情形：已经做过动作之后，某个隔离批次返回 `Err(Journal)`。
  - 处理照 W12 补单 01：这个批次和后面的批次都不再跑，条目按“因日志写不进去未处理”计入 `journal_note_zh` 的 N，记录照存，状态 `stopped`。
  - 什么都还没做时，照旧整次返回 `JOURNAL_MESSAGE`。
- **“做过动作”看条目状态**：`deleted`、`partial`、`moved` 都算，0 字节的也算；不再看释放或移动的字节数。
- **`journal_note_zh` 的措辞**：
  - N > 0：“清理日志没写全，后面的 N 项没有清”（不变）；
  - N = 0：“清理日志没写全，这次要清的都已处理”。
- **隔离失败的原因用中文**：组说明“没能放进隔离区：<原因>”里的原因，按执行器的错误给：

| 错误 | 原因 |
|---|---|
| `InvalidPlan` | 清理计划无效 |
| `Native` | 文件操作失败 |
| `Unsupported` | 这台电脑不支持 |
| `Journal` | 日志写不进去 |
| `Overflow` | 数量超出范围 |

- **一项都没进隔离区时，结果里的 `quarantined` 为 null**。

### 2.4 测试

- 标记 `SERVICE_W13_FRESH`（2.1）、`SERVICE_W13_CLUE`（2.2）、`SERVICE_W13_JOURNAL`（2.3），加在已有测试函数里，测试个数不变。
- **2.1**：
  - 跳过一张卡后，结论 `stale` 为 false、版本加一，其余卡片还能 `conclusion_decide`；
  - 跳过前准备的计划 `clean_start` 返回 `stale`；
  - 移除后同样不过期，条目恢复。
- **2.2**：泄漏簇里有不到 24 小时的成员时，从卡片跳过整组，线索与卡片都没了；只跳过部分成员时线索还在。
- **2.3**：
  - 经过 `clean_start` 调用执行器那一层，注入“前一批动过一项、后一批返回 `Err(Journal)`、再后一批”；断言后两批都没调用执行器，N 等于两批的项数，记录可读；
  - 前面只动过 0 字节的项时同样照存；
  - N = 0 时的措辞；
  - 各错误的中文原因；
  - 全部未跑时 `quarantined` 为 null。
- **旧断言获准迁移**：
  - “跳过后结论过期、原因‘跳过名单变了’”改为结论不过期、计划作废；
  - 隔离失败说明里的英文原因改为中文；
  - 全部未跑时的 `quarantined`。

  回执逐条写原值 → 新值 → 为什么。
- **`service_trends_locations` 的计时**：测试里扫描的结束时间是“假时钟起点 + 真实耗时”，机器忙时第二次扫描会落在假时钟“现在”之后，被趋势页筛掉。改测试：取趋势前把假时钟往后拨，或用别的办法让结果不受真实耗时影响。不改产品代码，不加墙钟时限。

## 3. 规则（R1，`packages/junk-rules`）

### 3.1 依据的写法

- `sources` 里 `kind` 为 `local_observation` 的 `ref`，依次写：
  1. 日期（`YYYY-MM-DD`）；
  2. “维护者本机只读检查”或“维护者本机清理”；
  3. 看到了什么（目录名、个数、大小）。
- 依据里不写：
  - 路径分隔符 `\` 与 `/`；
  - 私有文档路径；
  - “总控”；
  - 第 0 节列的那些。
- 原来写在路径里的目录名，改用文字说，例如把“`.local/share/claude` 下的 versions”改为“Claude Code 本地目录里的 versions”。
- 数字与日期照原样。
- `official_doc` 的网址、`skill` 的写法不变。
- 数据版本改为 `2026-11-08.1`。规则条数、定位、等级与文案都不变。

### 3.2 条数与版本只断言一处

- `tests/rules_v1.rs` 顶部定义规则条数与数据版本两个常量，原来各处的字面值都改为引用它们。
- 以后加规则只改这两个常量。

### 3.3 测试（标记 `RULES_W13_SOURCES`）

- 每条规则每个 `local_observation` 的 `ref` 都以日期开头，且不含 `\` 与 `/`。
- 依据文字的旧断言照新写法迁移，回执逐条写原值 → 新值。

## 4. 界面样例与界面（U1，三份 `ui-fixtures*.json` 与 `apps/water/ui`）

### 4.1 样例换成虚构路径

- 三份样例：`contracts/checkup-v1/ui-fixtures.json`、`contracts/m3c-v1/ui-fixtures-m3c.json`、`contracts/m35-v1/ui-fixtures-m35.json`。
- 里面的真实路径、本机用户名、本机项目名，以及第 0 节列的那些，换成虚构的。
- 同一个真实值在三份里换成同一个虚构值，包括出现在 ID、线索文字、复制文字里的。
- 映射表写进回执，只写“原值的类别 → 新值”，例如“工作目录 → `D:\code\flick`”，不在回执里写原值。
- **键与类型一个不改**。服务的测试也读这三份，只核形状。回执里给出按键与类型逐层比对基线版本的结果。
- 换了路径后，界面上的长度、截断、排序可能变；测试与截图照新样例重做。

### 4.2 移除跳过后重读结论

- 跳过名单页点“移除”后，有结论时重读结论（`conclusion_get`），不再在本地把结论标为过期。配合第 2.1 节。
- 跳过一条之后照旧重读结论（现在就是这样）。

### 4.3 测试（标记 `UI_W13_FIXTURES`、`UI_W13_FRESH`）

- **`UI_W13_FIXTURES`**：
  - 三份样例里每个形如 `X:\…` 的路径，都不在盘根下名为 `new` 的目录里；

- **`UI_W13_FRESH`**：移除跳过后发出了 `conclusion_get`，结论没有被标为过期。
