# W14 补充 01：扫描报“根目录走完”，规则阶段的进度按它算（冻结）

2026-11-08，总控（Claude）冻结。补充 [W14](W14.md) 第 3.3 节，W14 其余部分不变。

## 0. 为什么要补

S1 交回受阻（11-08 20:03 JST），总控核实属实：

- W14 第 3.3 节要求规则位置阶段“按完成的目标数”算进度，但扫描包的 `ScanProgress` 只有 `group_id`、`category`、`visited_entries`、`found_bytes`，看不出哪个目标走完了。
- 扫描是**一趟**走完所有根目录：同一组在走的途中每 50 ms 报一次，碰到不匹配的目录会强制报一次，全部走完后再给每个目标各报一次。按回调次数数，会提前到顶；按组去重也分不出同组里的几个目标。
- 原来的服务就是按回调次数数的，这也是 99% 来得很早的一个原因。
- 第十四波计划第 1 节说“只改服务就能给出真实进度”，只对整盘空间统计阶段成立（`space_overview` 每 50 ms 报累计字节）。规则阶段没有现成的信号。

所以扫描包要加一个信号（第 1 节，J2 做），服务按它算（第 2 节，S1 做）。

## 1. 扫描包：`on_root_done`（J2，`packages/junk-scan`）

### 1.1 接口（只新增，不改已有的）

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct RootProgress {
    pub root: String,
    pub roots_done: u64,
    pub roots_total: u64,
    pub visited_entries: u64,
}

pub trait ScanObserver: Sync {
    fn on_progress(&self, progress: &ScanProgress);
    fn on_root_done(&self, _root: &RootProgress) {}
}
```

- `RootProgress` 从 `lib.rs` 导出，和 `ScanProgress` 放在一起。
- `on_root_done` 有空的默认实现，已有的观察者不用改。
- `ScanProgress` 不变；`on_progress` 什么时候报、报几次都不变。

### 1.2 含义（`scan_full` 与 `scan`）

- **根目录**：每个目标的起点。`Pattern` 取 `base`，`Marker` 与 `Discovery` 取 `root`。兜底用的 `Marker`（`fallback_for` 有值）不算。按扫描现有的规则不分大小写去重。
- **`roots_total`**：这次扫描里去重后的根目录个数，整次扫描不变。
- **每个根目录恰好报一次**，`roots_done` 从 1 数到 `roots_total`：
  - 实际走了的：它下面的子树全部走完之后才报；
  - 走的时候跳过的（不存在、不是目录、是重解析点、已经在更早的根目录里走过）：走到它时报；
  - 一开始就不走的（隔离区里的、在 git 工作区里的）：开始走之前按计划顺序先报。
- **`root`**：计划里第一个用到这个根目录的目标写的原样字符串（不改大小写）。
- **`visited_entries`**：报的那一刻已经看过的条目数，与 `ScanProgress` 同一个计数。
- 扫描中途停下（取消，或者预算用完、整趟提前结束）时，还没轮到的根目录不再报。`scan_full` 返回后不再报。
- `space_overview` 不调 `on_root_done`。

## 2. 服务：规则阶段的进度（S1，改 W14 第 3.3 节的两处）

- **`percent`**：规则位置阶段按“已报走完的根目录数 ÷ `roots_total`”算，占的范围照旧（没有整盘位置时 0～90，有时 0～40）；向下取整。`roots_total` 为 0 或扫描提前结束时，`scan_full` 返回就到这一段的终点。其余（只增不减、空间统计 40～94、`finishing` 95、最终 100）不变。
- **一个目标“走完”**：它的根目录（同样不分大小写）报过了。兜底目标跟着它兜底的那个目标。
- **`locations[].state`**：
  - `done`：这个位置的目标都走完了（整盘位置还要等空间统计，见 W14 第 3.3 节）；
  - `running`：有目标还没走完，但它的组已经出现在 `on_progress` 里，或者它有目标已经走完；
  - `waiting`：其余。
- `categories` 里的完成情况同样按“目标走完”算。
- 同一组在途中重复的 `on_progress`、强制报的 `on_progress` 都**不算**目标走完。
