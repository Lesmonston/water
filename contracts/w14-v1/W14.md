## 0. 各单共同的

### 0.1 公开前的写法

照 [W13](../w13-v1/W13.md) 第 0 节：
- 不写本机用户名、本机路径、本机其它项目名、私人邮箱；
- 测试与样例里的路径用虚构的（`C:\Users\alice\…`、`D:\code\demo-app\…`）；
- 不写私有流程的引用（验收、派单、交接的文档路径，工单号，“总控”）。

### 0.2 英文的写法

- 美式英文，句子式大小写（只有句首与专有名词大写），不用感叹号，不用表情。
- 短句，说结果不说过程；和中文一样“结论先行”。
- 专有名词照第 7 节词汇表。各单都按这张表写，不另起译名。
- 数字与大小：`1.2 GB`、`<1 MB`、`369,510`；“约”写 `about`。
- 日期：`Nov 8`，带时间 `Nov 8, 14:05`（24 小时制），跨年时 `Nov 8, 2025`。
- 相对时间：`just now`、`5 min ago`、`3 h ago`；超过一天用日期。
- 列举用 `, ` 与 `and`，不用中文顿号。

### 0.3 测试

- 测试个数不变，新断言加在已有测试函数里。
- 不加新的墙钟时限断言。
- 依赖不变：不改 `Cargo.toml` 的依赖、`Cargo.lock`、`package.json`。

## 1. 双语的总规则（S1、H1、U1 都遵守）

### 1.1 语言与选择

- 支持两种语言：`zh`（简体中文）与 `en`（英文）。
- 用户的选择存在界面的 `localStorage`，键 `flick.language.v1`，值 `system`、`zh` 或 `en`，默认 `system`。服务与设置文件里不存语言。
- `system` 的解析：
  - 取宿主 `app_info.system_language`（第 4.1 节）。
  - 这个值为空或没有这个键时，取 `navigator.language`。
  - 以 `zh` 开头（不分大小写，含 `zh-TW`、`zh-HK`）就用 `zh`，其余都用 `en`。
- 切换立即生效，不重启，不重新体检。

### 1.2 文字从哪来

| 来源 | 怎么出英文 |
|---|---|
| 界面自己的文字（按钮、标题、提示、对话框、空状态、`aria-label`、`title`） | 界面里的字符串表（第 6.1 节） |
| 服务与宿主经 IPC 返回的文字 | 每个 `<名字>_zh` 旁边配一个 `<名字>_en`（第 1.3 节） |
| 规则的说明 | 规则数据里的英文字段（第 2 节），服务照第 1.3 节转出去 |
| 给 agent 的线索复制文字 | `copy_text` 旁边配 `copy_text_en`，界面按当前语言选 |

### 1.3 `_en` 兄弟字段

- 服务与宿主经 IPC 返回的 JSON 里，任何对象有字符串键 `<名字>_zh`，就同时有 `<名字>_en`：
  - `_zh` 是字符串时，`_en` 也是非空字符串；
  - `_zh` 是 `null` 时，`_en` 也是 `null`；
  - `_zh` 是字符串数组时，`_en` 是一样长的字符串数组。
- `copy_text` 配 `copy_text_en`，规则同上。
- 错误：`{code, message_zh}` 变成 `{code, message_zh, message_en}`，界面与宿主之间、服务与宿主之间都一样。
- **旧数据**：这一波之前存下的记录、设置里的跳过名单等，只有中文。读出来时 `_en` 填与 `_zh` 相同的中文（英文界面里旧记录照旧显示中文）。这一波之后新存的，两种都存。
- **界面的取法**：当前语言是 `en` 时，取 `_en`；没有这个键（例如旧样例）就退回 `_zh`。`zh` 时只取 `_zh`。
- 形状比对：服务测试里拿样例比对键的地方（`shape`），比对前**两边都去掉**以 `_en` 结尾的键与 `copy_text_en`。三份 `contracts/*/ui-fixtures*.json` 本波不改。

### 1.4 逻辑不靠中文句子

- 代码不再拿中文句子做判断（现在有：结论里认“似乎已卸载”“已脱离 git”，`m35` 里认“在程序目录 ”开头，扫描进度里比对“你加的位置 · …”）。改成代码或结构化字段。
- 新存的记录带代码；读这一波之前的旧记录时，仍然认得旧的中文写法（兼容），测试覆盖新旧两种。

## 2. 规则的英文（R1，`packages/junk-rules`）

### 2.1 字段

每条规则在对应的中文字段旁边加英文字段：

| 中文 | 英文 | 要求 |
|---|---|---|
| `title_zh` | `title_en` | 必填，2～48 个字符 |
| `what_zh`、`why_zh`、`after_zh` | `what_en`、`why_en`、`after_en` | 必填，4～320 个字符 |
| `owner_zh` | `owner_en` | 必填，1～64 个字符；中文值本来就是英文名（如 `Visual Studio Code`）时照抄 |
| `in_use_zh`、`fix_hint_zh`、`advice_zh`、`retention_zh` | `in_use_en`、`fix_hint_en`、`advice_en`、`retention_en` | 与中文同有同无，4～320 个字符 |

- 英文字段只含可打印字符，不含中文字符。
- `sources[].ref` 不翻译。

### 2.2 Rust 接口（S1 照这个用，冻结）

- `Rule` 加公开字段：
  - `title_en: String`、`owner_en: String`、`what_en: String`、`why_en: String`、`after_en: String`；
  - `fix_hint_en: Option<String>`、`advice_en: Option<String>`、`in_use_en: Option<String>`、`retention_en: Option<String>`。
- `RuleText`（`Rule::text()` 的返回）照同样的名字加英文字段。
- 解析器把这些键加进白名单，并照第 2.1 节检查。
- 自带的 `rules/windows.json` 全部 118 条都要有英文；数据版本改为 `2026-11-08.2`。

### 2.3 英文怎么写

- 照第 0.2 节与第 7 节词汇表。
- 意思与中文一致，不增不减。
- 不照字面硬翻，读起来要像英文产品文案：
  - `title_en` 写清是什么东西，例如 `Old Chrome versions`；
  - `what_en`、`why_en`、`after_en` 各一两句。

## 3. 服务（S1，`packages/water-service`）

### 3.1 英文

- 照第 1.3 节，所有经 IPC 返回的 `_zh` 都配 `_en`。包括：
  - 结论、卡片、折叠、线索与它们的 `copy_text`；
  - 趋势与预测的说明、历史摘要；
  - 清理与隔离的说明和原因、查重的原因；
  - 位置与进度里的名字；
  - 错误。
- 规则带来的文字取规则的英文字段（第 2.2 节）。
- 服务运行时拼的句子，每一句都要有英文版本，按第 0.2 节的格式写日期与数字。
- 两份大小文字的函数（`m35::amount`、`views::amount`）各出中英两种。
- 新存的记录（体检记录里的条目说明、清理记录、事件摘要、隔离区的组名、跳过名单的标题）两种语言都存。键名照第 1.3 节加 `_en`，旧记录照第 1.3 节兼容。
- 第 1.4 节：去掉以中文句子做判断的逻辑。

### 3.2 错误

- `IpcError` 加 `message_en: String`；每个错误码与那两条自带说明的 `invalid`（加的位置太宽、不支持的文件系统）都有英文。
- 宿主里唯一构造 `IpcError` 的地方（`apps/water/host/src/service.rs` 的 `HostPicker::pick` 两处）由 H1 改；S1 不改宿主，宿主在 S1 与 H1 一起合入前编译不过，这是预期的（第十四波计划第 4 节）。

### 3.3 扫描进度

`scan_progress` 的键不变，只改取值：

- **`state`**：
  - `running`：规则位置与整盘空间统计都在这个状态里；
  - 新增 `finishing`：所有位置都做完之后，到记录存好之前（占用检查、生成结论、写盘）；
  - 之后照旧是 `completed`、`partial`、`cancelled`、`failed`。
- **`locations[].state`**：
  - `waiting`、`running`、`done` 照旧；
  - 新增 `space`：这个盘的整盘空间统计正在跑；
  - 整盘位置要等它的空间统计结束才算 `done`。
- **`locations[].label_zh` / `label_en`**：始终是位置名本身，不再改成“· 空间分布”。
- **`found_bytes`**：只算规则位置找到的可清空间。整盘空间统计数到的字节**不计入**。
- **`percent`**：整数 0～100，同一次体检里只增不减；只有进入最终状态时才是 100。
  - 没有整盘位置时：规则位置阶段按完成的目标数占 0～90；`finishing` 为 95。
  - 有整盘位置时：规则位置阶段占 0～40；空间统计阶段占 40～94，按“已统计字节 ÷ 这些盘开始体检时的已用字节（总量减可用）”算，超出时停在 94；`finishing` 为 95。
- **`categories`**：照旧，每个类别带它已找到的字节，供界面画方块（第 6.4 节）。

### 3.4 测试

- `shape` 照第 1.3 节去掉 `_en` 键再比。
- 新加一个检查：遍历各命令的返回，所有 `_zh` 都有配对的 `_en`，类型照第 1.3 节。
- 进度：用假平台的整盘位置，核对状态序列 `running` → 位置 `space` → `finishing` → 最终状态；`percent` 只增不减、空间统计阶段走在 40～94 之间、`found_bytes` 不含空间统计的字节。
- 第十三波遗留：`service_trends_locations` 一类趋势测试把假时钟往后拨 60 秒，真实扫描超过 60 秒时仍会抢跑。改成不受真实耗时影响（例如按扫描实际结束时间再往后拨），不加墙钟时限。

## 6. 界面（U1，`apps/water/ui`）

### 6.1 字符串表与切换

- 界面自己的文字全部放进一张字符串表（中英两种），取文字统一走一个函数。视图里不再直接写中文。
- 设置里加“语言 / Language”：`跟随系统`、`中文`、`English`，存法照第 1.1 节。
- `index.html` 的 `lang` 与标题随语言变：`Flick · 磁盘体检` / `Flick · Disk checkup`。
- 格式化（`format.mjs` 与视图里拼的）照第 0.2 节出两种：日期、相对时间（顺手修正：相对时间按本地时间算，不用 UTC）、“约”、列举、单位“盘”（`F 盘` / `Drive F:`）。
- 取服务文字照第 1.3 节；复制线索时复制当前语言的那份。
- 错误提示取 `message_en` / `message_zh`；界面自己的兜底错误也进字符串表。

### 6.2 主页面一屏放下

- 这些页面在默认窗口 1240×820 与最小窗口 1040×720 下，中英两种语言都**不出现页面级的纵向滚动**：
  - 首页、体检中、结论、清理确认、清理中、清理完成、隔离区、趋势、记录、设置。
- 长列表只在卡片内部、抽屉或详情页里滚动。
- 做法：收紧留白与卡片高度，去掉多余的说明文字（第 6.3 节）；不缩小字号到正文 13px 以下。
- 浏览器测试在两种窗口大小、两种语言下核对 `document.scrollingElement.scrollHeight <= innerHeight`。

### 6.3 文案收拾

- 去掉只是在描述图表或重复显而易见的说明。例如：
  - 体检中的“每秒一根 · 本次体检”“按已检查的文件估算”；
  - 图表上类似的副标题。
- 每页保留的说明不超过一行，必须告诉用户一件看图看不出来的事。
- 回执列出删掉与改写的每一条（原文 → 新文或删除）。

### 6.4 体检中这一页

- **进度照服务的阶段走**（第 3.3 节）：
  - 主数字取 `percent`；
  - 状态文字：
    - `running` 时“正在体检” / `Checking`；
    - 有位置在 `space` 时“正在统计整盘空间” / `Measuring the whole drive`；
    - `finishing` 时“正在整理结论” / `Putting the results together`。
  - 位置卡片按 `locations[].state` 显示等待、扫描中、统计整盘空间、完成。
- **完成后的下一步**：
  - 进入最终状态后照旧自动转到结论页；
  - `cancelled` 也转到结论页，并说明“已停止，下面是停之前查到的”；
  - 任何时候都不停在一个没有按钮的页面。
- **方块图**：
  - “发现的可清空间”这张卡用方块图（现有的 `treemap` 一类）替换现在的竖线图；
  - 每个类别一块，面积按 `categories[].found_bytes`，颜色用该类别的颜色，随进度长大；
  - 不加说明副标题，类别名与大小放在方块上或悬停提示里。
  - 颜色：沿用结论页现有方块图的样式（[v3 设计稿](../../docs/design/water-ui-v3/mockup.html)定稿的天蓝深浅），相邻类别用不同深浅区分；不用渐变。
  - 不新增设计 token：`styles/tokens.css` 必须与设计稿的 `tokens.css` 逐字节一致（界面检查器会核对）。

### 6.5 跳过之前准备的计划（第十三波遗留）

- 准备好计划后又跳过了一项，再确认清理时服务返回 `stale`。
- 这时界面重读结论：
  - 结论本身没有过期，就重新准备计划，回到确认页，提示“跳过名单变了，已按新的结论重新准备” / `The skip list changed, so the plan was prepared again`；
  - 结论确实过期，才照旧显示“结果已过期 · 重新体检”。

### 6.6 测试与截图

- 单元测试：字符串表两种语言的键完全一致、没有空值；格式化两种语言；`system` 的解析（`zh-TW` → `zh`、`en-GB` → `en`、空 → 退到 `navigator.language`）。
- 浏览器测试：
  - 已有的流程在英文下再走一遍主要页面；
  - 英文下页面里不出现中文字符（假数据里只有中文的旧记录除外）；
  - 一屏放下的检查（第 6.2 节）；
  - 进度阶段与方块图；
  - 第 6.5 节的重新准备。
- 浏览器假数据：英文用的 `_en` 放在 `apps/water/ui/tests/` 下本单自己的文件里，不改三份共享样例。
- 截图：
  - 每个主页面在 1240×820 下中英各一张；
  - 首页、结论与体检中在 1040×720 下中英各一张；
  - 名字照工单。
